# Frontend Meetup: компоненты и переиспользование логики

Пример лекции 11: Vue 3.5, TypeScript, Vite. Все показы выполняет преподаватель. Во время лекции студентам не требуется запускать проект.

Из корня репозитория:

```bash
npm ci
npm run dev:components-example
npm run check:components-example
npm run build:components-example
npm run preview:components-example
```

Для презентации достаточно `npm run dev:11`: она импортирует эти же компоненты, отдельный сервер приложения не нужен. Сборка отдельного приложения — `dist/` внутри этого каталога, с относительным base для подпапки.

В локальном режиме App содержит LocalMeetup, который владеет коллекцией. RegistrationForm хранит черновик и отправляет проверенный payload, SeatCountField использует defineModel, RegistrationList сообщает id через remove. MeetupPanel предоставляет обычный и именованные слоты. Данные живут только в памяти; перезагрузка возвращает Анну (2 места) и Бориса (1 место). Добавление не отправляется на сервер.

В режиме загрузки две RegistrationSearchPanel вызывают один useRegistrationSearch, но получают независимые состояние, запросы и кеш. Composable использует настоящие клиент и фабрику из `slides/public/examples/10-async-http/`, не копирует алгоритм. Для standalone-сборки три JSON-файла лежат в public/data; презентация читает уже существующие файлы лекции 10. Задержки и 503 имитируются, fetch и проверка ответа настоящие. Кеш — пять секунд; «Обновить» читает принудительно. Изменение условия ответа применяется при следующем запросе. Закрытие панели вызывает dispose.

Сценарий: добавить Веру (2), отправив Enter; итог 5. Найти и удалить Веру: итог 3, фокус возвращается в поиск. Перейти к загрузке, дождаться двух списков, в A выбрать Анну и сразу Бориса. A показывает Бориса, B остаётся прежним. Выбрать 503 и обновить: прежний список остаётся с ошибкой. Вернуть корректный ответ, начать медленную Анну, закрыть A. B продолжает работать, новое открытие A создаёт новый экземпляр.

Дополнительные лабораторные поверхности встроенных слайдов выбираются prop mode у App: counters, contract, props, lifecycle, lifecycle-tree, renderer, watch, search, local. В standalone по умолчанию full: оба прикладных режима. LifecycleLab намеренно позволяет оставить window-подписки для сравнения; сброс и удаление стенда снимают их все. Ничего не сохраняется в localStorage.

Сценарий лектора и границы опытов: `notes/11-vue-components.md` в корне репозитория. Документация: [Vue Composables](https://vuejs.org/guide/reusability/composables.html).

В режиме props сравниваются настоящий вход, ref с начальным снимком и computed с живым чтением. Отключение передачи проверяет default, а смена key пересоздаёт ребёнка. SeatCountField отключает автоматическое наследование attrs и передаёт их input; name="seats" попадает в FormData нативной формы.

Режим lifecycle-tree показывает настоящие setup/beforeMount/mounted/beforeUpdate/updated/beforeUnmount/unmounted у родителя и ребёнка. Журнал вынесен из наблюдаемого дерева. «Два изменения count» делает два присваивания в одном обработчике; «Изменить неиспользуемый ref» не должно вызывать update. После удаления и повторного создания setup выполняется заново.

Режим renderer сравнивает реальные ссылки на корневой DOM-элемент и статический span, а также useId экземпляра. Изменение текста/атрибута сохраняет ссылки; смена p/section меняет DOM при прежнем владельце; смена key RenderProbe создаёт новый экземпляр. MutationObserver наблюдает только сцену, а его записи не равны числу пересозданных компонентов. Для доступа к экземпляру и элементу стенд использует template refs и defineExpose как измерительный инструмент.

Для отдельного показа рендеринга откройте `/?demo=renderer` относительно адреса приложения. Параметр demo также принимает остальные перечисленные режимы; неизвестное значение возвращает полный стенд. Это средство запуска преподавательских демонстраций, не маршрутизация приложения курса.

Режим `?demo=watch` сравнивает настоящие watch(query, …, { immediate: true }) и watchEffect. Оба читают query и служебную метку diagnostic. «Изменить метку журнала» добавляет запись только в колонку watchEffect, новое имя — в обе. Это наблюдение вызовов без HTTP-загрузки; строки журналов сохраняют снимки значений каждого выполнения.

В панелях загрузки кнопка «Выбрать Бориса из кода» только присваивает query. Она не вызывает search напрямую и не создаёт DOM-событие change: загрузку запускает watcher. Повтор того же значения не запускает новый поиск; «Обновить» остаётся отдельной принудительной командой. Удаление панели вызывает окончательный dispose.

Режим `?demo=composable-hooks` показывает общий владелец хуков: два вызова useLifecycleTrace и собственные callbacks компонента. Создание и удаление дают записи A/B/Компонент для mounted и unmounted; журнал хранится у внешнего стенда. Очистка журнала не меняет существование компонента.
