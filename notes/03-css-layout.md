## 0:00–0:07. От размера элемента к раскладке

**[Слайд 1 — «Вёрстка средствами CSS»]**

Добрый день. На прошлой лекции мы разобрали, как отдельный элемент получает свой размер через блочную модель: `padding` создаёт внутреннее пространство, `border` рисует границу, `margin` отделяет соседей, а `box-sizing` определяет, кто считается в объявленной ширине.

Сегодня мы отвечаем на другой вопрос: как эти элементы занимают место относительно друг друга?

**[Слайд 2 — «Мы знаем размер карточки. Но кто определяет её место?»]**

К концу лекции у нас не будет набора разрозненных свойств. Будет одна модель: браузер уже располагает элементы по умолчанию — в нормальном потоке. Разработчик не рисует страницы по координатам. Разработчик выбирает модель раскладки и задаёт ограничения: направление, количество колонок, размер элементов, выравнивание.

**[Слайд 3 — «Браузер уже располагает элементы»]**

Покажем страницу Frontend Meetup без Flexbox, Grid и позиционирования. Она остаётся читаемой: заголовки, абзацы и карточки уже занимают место в нормальном потоке. Страница перестаёт напоминать макет из графического редактора: это документ, который умеет менять содержание и продолжать работать.

[В компоненте добавить текст в первую карточку и показать, как вторая сдвигается вниз.]

Главная формула этой лекции — четыре вопроса о раскладке:

1. В какой модели раскладки участвует элемент?
2. Остаётся ли он в нормальном потоке?
3. Откуда берётся доступное пространство?
4. Кто управляет размером — элемент, родитель или оба?

Каждый механизм лекции — нормальный поток, `display`, единицы, позиционирование, Flexbox и Grid — помогает отвечать на эти вопросы.

**[Слайд 4 — «Четыре вопроса о раскладке»]**

```
1. В какой модели раскладки участвует элемент?
2. Остаётся ли он в нормальном потоке?
3. Откуда берётся доступное пространство?

```

Эта последовательность будет повторяться в каждом разделе. Не нужно запоминать все свойства сразу. Нужно понимать, какой механизм за что отвечает и как он вписывается в одну картину.

## 0:07–0:18. Нормальный поток и display

**[Слайд 5 — «Структура документа определяет порядок»]**

HTML читается в порядке исходного кода. Браузер последовательно создаёт коробки и размещает их по правилам выбранной модели. Для большинства элементов это нормальный поток: следующий элемент появляется под предыдущим, а изменение размера одного сдвигает остальные.

Это не отдельное CSS-свойство. Это базовое поведение браузера, которое мы отключаем или переопределяем только когда оно не подходит.

**[Слайд 6 — «block — новая строка и заполнение ширины»]**

```css
article {
  display: block;
}
```

Блочная коробка начинается с новой строки, заполняет доступную ширину контейнера по горизонтали и подстраивает высоту под содержимое. Если добавить ещё одну карточку, она появится после предыдущей с учётом внешних отступов.

**[Слайд 7 — «inline — участие в строке текста»]**

```css
a {
  display: inline;
}
```

Строчная коробка участвует в строке. Она переносится вместе с текстом: если места не хватает, следующая коробка появляется под предыдущей на новой строке. Обычные `width` и `height` не управляют строчными коробками так же, как блочными.

**[Слайд 8 — «inline-block остаётся в строке, но получает размеры»]**

```css
.tag {
  display: inline-block;
  padding: 0.25rem 0.5rem;
}
```

Элемент остаётся частью строки, но получает самостоятельную прямоугольную коробку: для него работают размеры, вертикальные отступы и высота строки.

**[Слайд 9 — «display управляет двумя вещами»]**

`display` определяет внешнее поведение коробки и внутреннюю раскладку детей:

```css
.actions {
  display: flex;
}
```

`.actions` остаётся блочной коробкой в своём родителе. Но её непосредственные дети — `.actions__link` и `.actions__button` — становятся flex items и получают новые правила раскладки. Вложенное содержимое внутри ссылки не превращается автоматически в flex items: Flexbox управляет только непосредственными детьми.

Это правило повторяется для Grid: `display: grid` управляет только прямыми потомками контейнера.

**[Слайд 10 — «Что изменится при смене display?»]**

[Показать HTML:]

```html
<p>
  Начало
  <span class="tag">CSS</span>
  продолжение текста
</p>
```

[Сначала попросить аудиторию предсказать три результата:]

- `display: block` — тег займёт всю строку, «начало» и «продолжение» окажутся на разных строках;
- `display: inline` — тег не будет создавать прямоугольную коробку с размерами;
- `display: inline-block` — тег останется в строке, но получит самостоятельные размеры и вертикальные отступы.

[После предсказаний проверить результат интерактивно.]

**Проверка четырёх вопросов для display**

- **Модель:** normal flow; `block`, `inline` и `inline-block` меняют внешнее поведение коробки.
- **Поток:** элемент остаётся в нормальном потоке.
- **Пространство:** оно приходит от строки текста или содержащего блока.
- **Размер:** `block` заполняет доступную ширину, `inline` ограничен содержимым, `inline-block` получает собственную коробку.

## 0:18–0:28. Размеры и единицы

**[Слайд 11 — «auto — полноценное решение»]**

До единиц важно показать, что размер может вообще не задаваться явно:

```css
.card {
  width: auto;
}
```

Блочная коробка с `width: auto` заполняет доступную ширину контейнера. Высота определяется содержимым. Больше текста — выше карточка. Фиксированная высота может создать неожиданное переполнение, если текст не помещается.

**[Слайд 12 — «Единица выражает зависимость»]**

Каждая единица решает свой вопрос: **от чего должен зависеть размер?**

- `px` — конкретное значение без зависимости;
- `rem` — зависит от размера шрифта корневого элемента;
- `em` — зависит от размера шрифта текущего элемента;
- `%` — зависит от соответствующего размера содержащего блока;
- `vw`, `vh` — зависят от viewport;
- `fr` — зависит от свободного пространства grid-контейнера.

Не нужно учить каталог единиц. Достаточно уметь выбрать одну единицу по задаче.

**[Слайд 13 — «rem и em отвечают на разные вопросы»]**

```css
/* зависит от корневого шрифта — 1rem = текущий html { font-size } */
.card {
  padding: 1.5rem;
}

/* зависит от размера текста badge — меняется вместе с текстом */
.badge {
  padding: 0.25em 0.5em;
}
```

`rem` гарантирует стабильное пространство в масштабах всей страницы. `em` позволяет компоненту масштабироваться вместе со своим текстом.

**[Слайд 14 — «em масштабируется повторно внутри увеличенного шрифта»]**

Но у `em` есть риск вложенности:

```css
.list {
  font-size: 1.2em;
}
```

Вложенный список получает увеличенный шрифт ещё раз. 1,2 × 1,2 = 1,44. Это не ошибка, но её нужно предвидеть.

**[Слайд 15 — «Зависимость от контейнера vs зависимость от экрана»]**

```css
.card {
  width: 50%;
}
```

`%` выражает зависимость от соответствующего размера содержащего блока. В примере `width: 50%` — половина доступной ширины содержащего блока, а не экрана.

```css
.hero {
  min-height: 50vh;
}
```

`vw` и `vh` зависят от viewport — видимой области браузера. Они полезны, когда размер должен следовать за окном: полноэкранные секции, фоновые блоки. Для обычных отступов и внутренних размеров они не нужны.

Уточнение: на мобильных устройствах динамический браузерский тулбар может менять размер viewport. Современные `dvh`, `svh` и `lvh` решают эту проблему, но детальное применение оставим для лекции 4.

**[Слайд 16 — «Свободное пространство после gap и фиксированных размеров»]**

```css
.grid {
  grid-template-columns: 1fr 2fr;
}
```

`fr` — доля свободного пространства после вычета `gap` и других фиксированных размеров. Это единица Grid, а не универсальная единица размеров: во Flexbox пространство распределяется через `flex-basis`, `flex-grow` и `flex-shrink`.

**[Слайд 17 — «Решите по задаче, а не по памяти»]**

```
Тонкая граница          → 1px
Пространство карточки   → 1.5rem
Badge рядом с текстом   → 0.25em
Половина контейнера     → 50%
Доля grid-колонки       → 1fr
```

**Проверка четырёх вопросов для единиц**

- **Модель:** единица описывает зависимость размера, а не выбирает layout.
- **Поток:** единицы сами по себе не выводят элемент из потока.
- **Пространство:** база берётся из корневого шрифта, текущего шрифта, содержащего блока, viewport или свободного пространства Grid.
- **Размер:** сначала определить зависимость, затем выбрать `px`, `rem`, `em`, `%`, `vw`/`vh` или `fr`.

## 0:28–0:41. Позиционирование

**[Слайд 18 — «Позиционирование: поток и система координат»]**

Каждый позиционированный элемент отвечает на два вопроса:

1. Остаётся ли он в нормальном потоке?
2. Относительно какой области считаются его смещения?

Для каждого значения `position` достаточно запомнить один факт: где элемент находится и от чего считается его координата.

**[Слайд 19 — «Стандартное положение в потоке»]**

```css
.element {
  position: static;
}
```

`static` — значение по умолчанию. Элемент остаётся в потоке. Свойства `top`, `left`, `right`, `bottom` и любые `inset-*` не перемещают статически позиционированный элемент.

**[Слайд 20 — «Сохраняет место в потоке»]**

```css
.card {
  position: relative;
}
```

Элемент сохраняет своё место в нормальном потоке. Другие элементы не сдвигаются, и пустое место остаётся ровно таким, каким оно было бы без позиционирования.

Практическое назначение `relative` — создать систему координат для абсолютно позиционированных дочерних элементов.

**[Слайд 21 — «Выходит из потока, привязывается к предку»]**

```css
.card {
  position: relative;       /* parent */
}

.card__badge {
  position: absolute;
  inset-block-start: 1rem;
  inset-inline-end: 1rem;
}
```

`absolute` выводит элемент из нормального потока. Другие элементы не резервируют для него место — badge накладывается поверх содержимого.

Координаты считаются относительно ближайшего предка, который создаёт containing block. В типичном случае это ближайший предок с `position`, не равным `static`. Если такого предка нет, используется начальный containing block.

Если badge оказался в неожиданном месте, первый шаг диагностики — проверить containing block: найти ближайшего позиционированного родителя.

**[Слайд 22 — «Обычно привязан к viewport»]**

```css
.fab {
  position: fixed;
  bottom: 1rem;
  right: 1rem;
}
```

`fixed` также выводит элемент из потока. Обычно координаты считаются относительно viewport, а при прокрутке элемент остаётся на месте. Некоторые свойства предков, например `transform`, могут изменить containing block.

Подходит для независимых от структуры документа элементов: плавающая кнопка, уведомление, оверлей. Не подходит для основной раскладки страницы.

**[Слайд 23 — «Начинается в потоке, прилипает при прокрутке»]**

```css
.schedule__day {
  position: sticky;
  top: 1rem;
}
```

`sticky` ведёт себя как `relative`, пока элемент не достигнет заданного порога. Затем он «прилипает» к краю ближайшего scroll container и остаётся ограниченным своим контейнером.

Главные условия: задать порог, например `top`, и не сломать ожидаемый scroll container свойствами `overflow` у предков. Собственная прокрутка родителя не обязательна: sticky может работать при прокрутке документа.

**[Слайд 24 — «Порядок перекрытия, а не раскладка»]**

```css
.card__badge {
  position: absolute;
  z-index: 10;
}
```

`z-index` управляет порядком наложения внутри stacking context. Он работает для positioned elements, а также для flex и grid items. Он не исправляет неправильную раскладку и не перемещает элементы в потоке.

Для новичка полезна одна проверка: достаточно ли уменьшить внешнее пространство `margin` или изменить размер, а не пытаться «поднять слой» поверх ошибки layout.

**[Слайд 25 — «Почему badge оказался в углу страницы?»]**

[Упражнение. Показать код:]

```css
.card__badge {
  position: absolute;
  top: 0;
  right: 0;
}
```

Badge появился в правом верхнем углу страницы вместо карточки. Студенты называют причину: у badge `position: absolute`, но карточка не позиционирована, поэтому containing block — страница. Решение: добавить `.card { position: relative; }`.

**Проверка четырёх вопросов для positioning**

- **Модель:** normal flow или позиционирование относительно containing block.
- **Поток:** `static` и `relative` сохраняют место; `absolute` и `fixed` выходят из потока; `sticky` начинает в потоке.
- **Пространство:** координаты считаются от содержащего блока, viewport или ближайшего scroll container.
- **Размер:** координаты задаются смещениями, а размер остаётся отдельным вопросом.

## 0:41–0:59. Flexbox

**[Слайд 26 — «Flexbox — оси, выравнивание и пространство»]**

Flexbox располагает непосредственных детей контейнера вдоль основной оси и управляет свободным пространством.

Одномерная — потому что раскладка идёт вдоль одной оси, а перенос создаёт дополнительные линии. Flexbox не строит двумерные сетки с пересекающимися строками и колонками.

**[Слайд 27 — «Flexbox управляет только прямыми потомками»]**

```css
.actions {
  display: flex;
}
```

Только непосредственные дети `.actions` становятся flex items. Вложенный `<span>` внутри ссылки не превращается в flex item: Flexbox управляет только прямыми потомками контейнера.

Это ограничивает область управления, но полезно: можно контролировать, что именно попадает в раскладку.

**[Слайд 28 — «flex-direction определяет оси»]**

```css
.actions {
  display: flex;
  flex-direction: row;      /* по умолчанию */
}

.list {
  display: flex;
  flex-direction: column;   /* вертикально */
}
```

`flex-direction` определяет main axis и cross axis. Изменять их не случайно: `justify-content` всегда по основной оси, а `align-items` всегда поперёк.

**[Слайд 29 — «justify по основной оси, align — поперёк»]**

```css
.actions {
  display: flex;
  justify-content: space-between;
  align-items: center;
}
```

- `justify-content` распределяет свободное пространство по **основной** оси;
- `align-items` выравнивает элементы по **поперечной** оси.

Если поменять `flex-direction`, экранное направление свойств меняется, но смысл остаётся прежним: `justify-content` — по основной оси.

**[Слайд 30 — «gap задаёт расстояние между элементами, wrap — разрешает перенос»]**

```css
.tags {
  display: flex;
  flex-wrap: wrap;
  gap: 0.75rem;
}
```

`gap` задаёт расстояние между flex items. Он не добавляет отступ по краям контейнера и не зависит от направления оси.

`flex-wrap: wrap` разрешает перенос элементов на следующую строку, когда им не хватает места.

**[Слайд 31 — «basis, grow и shrink делят пространство»]**

```css
.card {
  flex: 1 1 16rem;
}
```

`flex` — сокращение трёх значений:

- `flex-basis: 16rem` — начальный размер элемента по основной оси;
- `flex-grow: 1` — получить долю свободного пространства;
- `flex-shrink: 1` — уменьшиться при нехватке места.

**[Слайд 32 — «Соберите строку навигации с кнопками»]**

Пример: toolbar с названием события слева и кнопками навигации справа:

```css
.toolbar {
  display: flex;
  justify-content: space-between;
  align-items: center;
  gap: 1rem;
}

.toolbar__title {
  margin-right: auto;       /* или justify-content: space-between */
}
```

[После построения уменьшить ширину контейнера и показать, где элементы начинают переноситься.]

**[Слайд 33 — «flex-direction меняет оси, а не смысл свойств»]**

```css
.card-group {
  display: flex;
  flex-direction: column;
  align-items: stretch;     /* теперь растягивает горизонтально */
}
```

Этот слайд — проверка понимания осей. При `column` основная ось вертикальна, а поперечная горизонтальна. `align-items: stretch` растягивает элементы по горизонтали, а не вертикали.

**Проверка четырёх вопросов для Flexbox**

- **Модель:** одномерная раскладка непосредственных детей.
- **Поток:** flex items участвуют в раскладке контейнера, но уже по правилам основной и поперечной осей.
- **Пространство:** свободное место распределяется через `justify-content`, `gap`, `flex-grow` и `flex-shrink`.
- **Размер:** исходный размер задаёт `flex-basis`, итоговый — комбинация `basis`, `grow` и `shrink`.

## 0:59–1:16. Grid

**[Слайд 34 — «Grid — строки, колонки и пространство»]**

Grid задаёт строки и колонки контейнера и размещает элементы по двум осям одновременно.

Grid позволяет задавать количество колонок, их ширину и промежутки между ними. Элементы размещаются по очереди в ячейках сетки, а разработчик решает: занимает элемент одну ячейку или несколько.

**[Слайд 35 — «grid-template-columns задаёт колонки контейнера»]**

```css
.schedule {
  display: grid;
  grid-template-columns: 12rem 1fr;
  gap: 1rem;
}
```

`grid-template-columns` задаёт треки — строки и колонки сетки. `12rem 1fr` создаёт две колонки: первая фиксированная, вторая получает оставшееся свободное пространство.

**[Слайд 36 — «fr — доля свободного пространства после gap»]**

```css
.cards {
  grid-template-columns: 1fr 2fr;
}
```

`fr` — доля свободного пространства после вычета `gap` и других размеров. Если первая колонка `1fr`, вторая `2fr`, а gap 1rem, то вторая колонка получает в два раза больше свободного места, но не обязательно в два раза больше всей ширины.

**[Слайд 37 — «repeat() сокращает описание одинаковых колонок»]**

```css
.cards {
  grid-template-columns: repeat(3, 1fr);
}
```

`repeat()` сокращает описание одинаковых треков. Три одинаковые колонки заменяют `1fr 1fr 1fr`.

**[Слайд 38 — «Grid расставляет элементы по очереди»]**

Если позиции элементов не заданы явно, Grid расставляет их по очереди: слева направо, сверху вниз. Это означает, что для галереи из шести карточек не нужно назначать координаты каждой: Grid делает это сам.

Изменение количества карточек сдвигает сетку без поломки раскладки: добавленная карточка появляется после предыдущей, а новые строки формируются автоматически.

**[Слайд 39 — «Элемент может занять несколько треков»]**

```css
.featured {
  grid-column: span 2;
}
```

`grid-column: span 2` заставляет элемент занять две колонки. Альтернативный синтаксис — указать номер строки или колонки:

```css
.featured {
  grid-column: 1 / 3;
}
```

**[Слайд 40 — «Описать каркас страницы в одном месте»]**

```css
.page {
  display: grid;
  grid-template-areas:
    "header header"
    "nav    main"
    "footer footer";
}

.page__header { grid-area: header; }
.page__nav    { grid-area: nav; }
.page__main   { grid-area: main; }
.page__footer { grid-area: footer; }
```

Именованные области — способ описать схему всей страницы в одном месте. Когда структура стабильна и действительно двумерна, области дают читаемую карту.

Не использовать области для каждой карточки: там достаточно автоматического размещения или `span`.

**[Слайд 41 — «Попробуйте сами — добавьте карточку, смените колонки»]**

[Предложить добавить карточку, переключить колонки на 2 и 4 и включить `grid-column: span 2`. После каждого шага назвать изменившуюся часть Grid.]

**Проверка четырёх вопросов для Grid**

- **Модель:** двумерная раскладка строк и колонок.
- **Поток:** элементы размещаются в ячейках автоматически, если позиции не заданы явно.
- **Пространство:** треки получают доступное пространство контейнера; `fr` делит остаток после `gap` и фиксированных размеров.
- **Размер:** `grid-template-columns`, `grid-template-rows`, `span` и named areas задают геометрию.

## 1:16–1:25. Выбор модели и сборка страницы

**[Слайд 42 — «Frontend Meetup использует несколько моделей»]**

Frontend Meetup собирает все механизмы вместе:

- **Нормальный поток** — последовательность header, секций и карточек;
- **Flexbox** — навигация в header;
- **Grid** — основной каркас страницы и карточки программы;
- **Absolute positioning** — badge «Бесплатно» внутри карточки;
- **Sticky** — заголовок текущего дня программы.

Один механизм не запрещает другой. Grid-контейнер может содержать flex items, а absolute badge — находиться внутри grid-карточки. В реальном примере сначала найти каждый механизм, затем объяснить, какую задачу он решает.

[Попросить найти в примере нормальный поток, Flexbox, Grid, absolute badge и sticky-заголовок. Цвета легенды: серый — поток, синий — Flexbox, зелёный — Grid, красный — positioning.]

**[Слайд 43 — «От простого к нужному»]**

```
Элементы следуют содержанию?         →  Оставить поток
Нужна одна ось или группа элементов?  →  Flexbox
Нужны строки и колонки вместе?        →  Grid
Элемент накладывается или привязан?   →  Positioning
Проблема только в размере?            →  Проверить единицы, не менять модель
```

Начинаем с потока. Применяем Flexbox, когда нужна ось и выравнивание. Переходим к Grid, когда нужны двумерные соотношения. Используем positioning для наложения или привязки к области, не меняя структуру.

6. Откуда берётся свободное пространство?

Последовательность не случайная: от общего к частному, от родителя к элементу.

**[Слайд 46 — «Хорошая раскладка описывает отношения, а не координаты»]**

> Хорошая раскладка не хранит снимок страницы в координатах. Она описывает отношения между элементами и продолжает работать, когда меняется текст, количество карточек и доступное пространство.

На следующей лекции добавим адаптивность: media queries, responsive design, transforms, transitions, animations и CSS variables помогут сохранить эти отношения при изменении условий.
