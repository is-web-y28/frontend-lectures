# Лекция 10: маршрут и репетиция

Основной маршрут: 81 слайд, шесть глав. Приложения A–G не входят в план занятия. Числа ниже — контрольные точки репетиции, не результат проведённого занятия. На экране учебные длительности не показываются.

| К отметке | Действие и проверяемый результат |
| --- | --- |
| 6 минут | Прогноз count до callback записан; объяснено наблюдаемое ожидание. |
| 30 минут | Один JS-поток отделён от браузерного ожидания. Показаны рабочий callback, callback hell и тот же отчёт через Promise. Базовый порядок проверен настоящим JS; круг остановлен у занятого стека и у checkpoint. Вложенная микрозадача разобрана до добавления M3 в хвост, без повторного полного запуска. |
| 39 минут | Сравнены fulfilled и pending await. В pending продолжения ещё нет в микрозадачах; другое нажатие реально выполняется. Тот же отчёт прочитан через await: изменена запись, а не зависимости и поток. |
| 52 минуты | После практики клиент отклоняет 503 до json, неверные поля — после разбора, а [] принимает как успех. Практика: две минуты в парах и короткий разбор. |
| 71 минута | Объект state отделён от DOM. Гонка наблюдалась без защиты; разобраны номер, защита catch и сигнал отмены. Практика старого отказа: четыре минуты с объяснением каждой записи состояния. |
| 78 минут | Полный JS-сценарий: все записи → Анна → Борис → ошибка обновления → восстановление. Отдельный стенд кеша не запускается: это приложение F. Фабрика сопоставлена с уже знакомыми latest/controller/cache/commit. |
| 85 минут | Перенос во Vue: тот же исходник алгоритма и другая связь с DOM. Повторяются лишь смена поиска и ошибка обновления, а не весь длинный JS-сценарий. |
| 90 минут | Самостоятельный ответ на три ситуации, обсуждение и вопросы. Две минуты — индивидуальные ответы, одна — разбор; остальные две — вопросы. |

Для круга выбрать обычный темп и нажать «Запустить». Остановить после регистрации таймера: готовый T не вытесняет стек. Продолжить до checkpoint и остановить ещё раз: перед выбором следующей задачи нужно завершить микрозадачи. Во вложенном примере достаточно увидеть M2 перед новой M3. В await достаточно одного сравнения уже готового и pending Promise. Постоянное вращение при занятом стеке было бы неверным объяснением; маркер показывает текущую ответственность цикла.

Во время репетиции фиксируйте фактическую отметку после каждой главы, включая работу мышью, чтение исходника и ответы вслух. Если точка запаздывает, сначала исключите повторный запуск с тем же вопросом и необязательные переключения селектора. Не ускоряйте объяснение pending Promise или проверку ответов ради дополнительных вариантов. При устойчивом превышении бюджета разделите занятие по границе завершённого JS-сценария и переноса во Vue; не объявляйте хронометраж проверенным до прогона.

Минимальные входные знания: функции и callback, массивы, DOM из 06–07; замыкания и модули из 07; unknown и граница проверки из 08; reactive, computed и шаблон из 09. Фабрика загрузки не вводит новую систему состояния: её переменные показаны перед соединением с интерфейсом.

Связка первых глав: слайд 8 явно ограничивает однопоточность одним агентом страницы; слайд 11 связывает внешний источник готовности, очередь и event loop. В слайдах 13–14 сначала работает обычный callback таймера, затем появляется callback hell из трёх зависимых операций отчёта. Callback сам по себе не означает асинхронность: у map он синхронный. Договор readMeetup/readRegistrations/createReport здесь учебный, реализации HTTP ещё не введены. Слайд 15 определяет Promise до появления new Promise: объект возвращается сейчас и представляет успешное значение или причину отказа операции; в примере сам объект отличается от будущего числа 3. На слайде 29 эти операции уже возвращают Promise: каждый return связывает шаг с общей цепочкой, один catch получает отказ. На слайде 37 используются те же Promise-функции с await. Спросить, что изменилось в выполнении: зависимости остались последовательными, второго JS-потока не появилось, изменилась запись продолжений. Не разбирать три версии как три отдельных API и не обещать, что Promise автоматически устраняет блокирующее вычисление или любую вложенность.

Итоговые ответы: (1) pending await ещё не готов к постановке в микрозадачи, обработчик другого события может выполниться; (2) успешный пустой B сохраняет success, старый отказ A игнорируется; (3) reactive не проверяет HTTP, response.ok остаётся обязанностью общего клиента. Ошибочный ответ разбирается через соответствующий механизм, а не через повтор названия API.

Перенос на сервер проекта: заменить учебный источник реальным URL, не менять правила клиента и владельца состояния. В Network проверить реальный статус, тело и порядок завершения; повторить пустой ответ, отказ и два запроса. Управляемые задержки и 503 стенда подписаны как имитации и не доказывают скорость или настройки реального сервера.

## Необязательное приложение G: HTTP-клиент Axios

Слайды 105–115 — отдельный разбор после завершения основного маршрута. Начать с повторяющихся обязанностей fetch-клиента, затем показать первый запрос, экземпляр с настройками и сохранённую границу parseRegistrations. get<Registration[]> не проверяет поля во время выполнения. В исполняемом клиенте используется get<unknown>, строгий разбор JSON и тот же валидатор, что у fetch.

В стенде сравнить корректный список, пустой успех, неверные поля и повреждённый JSON. У неверных полей ожидается обычный Error валидатора; у повреждённого JSON — SyntaxError для fetch и AxiosError/ERR_BAD_RESPONSE для настроенного Axios. Для отмены включить Slow 3G и отключить кеш в Network: без ограничения скорости локальный файл может прийти раньше нажатия. Отмена Axios определяется через isCancel, а не имя AbortError. После опыта вернуть обычную скорость. Сброс и уход со слайда прерывают запрос; поздний ответ не должен восстановить состояние.

Стенд читает реальные статические файлы; HTTP 503 и серверная фильтрация здесь не имитируются. Пример с /api/ и params — код для сервера проекта с согласованным договором фильтрации, не адрес работающего API этой презентации. При переносе сохранить load(query, signal), защиту stale success/catch и кеш; во Vue меняется связь с DOM, а не эти правила. Перехватчики подключать на время жизни экземпляра, возвращать response или пробрасывать отказ, при необходимости снимать через eject. Это материал о выборе клиента, а не обязательное требование использовать Axios.
