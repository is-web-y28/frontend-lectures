## 0:00–0:08. HTML уже есть — зачем CSS

**[Слайд 1 — «Основы CSS»]**

На прошлой лекции мы построили честный HTML-документ. В нём есть `header`, `nav`, `main`, заголовки, ссылка, форма и кнопка. Если отключить все авторские стили, человек всё равно понимает, где он находится и что может сделать. Это не промежуточная заготовка, а основа страницы.

**[Слайд 2 — «HTML и CSS решают разные задачи»]**

HTML отвечает: «Это ссылка», «Это основной заголовок», «Это поле формы». CSS отвечает: «Ссылка выглядит так, заголовок имеет такой размер, вокруг карточки есть такое пространство». JavaScript позже ответит: «Что происходит после действия пользователя».

Если у кнопки исчезнет синий фон, она всё ещё останется кнопкой. Если у ссылки изменится цвет, она всё ещё ведёт к ресурсу. А если заменить кнопку `div`-ом только потому, что так проще раскрасить, CSS скроет проблему лишь на время.

**[Слайд 3 — «Базовое представление и авторский CSS»]**

На экране два варианта одного фрагмента Frontend Meetup. HTML одинаковый. Слева документ показывается с базовым представлением браузера: у него уже есть шрифты, размер заголовка и ссылка. Справа авторский CSS меняет шрифт, границу, фон и цвет, но не назначение элементов.

Это единственное намеренное сравнение «до/после» в лекции. Дальше разбираем, почему возникает каждый итоговый стиль, а не выдаём каждое правило за создание всей карточки.

**[Слайд 4 — «CSS»]**

CSS — Cascading Style Sheets, каскадные таблицы стилей. Слово *cascading* здесь главное. К одному элементу обычно подходят несколько правил: одно задаёт цвет текста, другое — отступ, третье — состояние при фокусе. Браузер выбирает итоговое значение отдельно для каждого свойства.

**[Слайд 5 — «Шесть шагов при отладке CSS»]**

К концу лекции будет не коллекция свойств на память, а короткая последовательность: проверить допустимость значения, затем селектор, каскад, наследование, состояние и размер. Это не значит, что каждый вопрос нужен для каждого правила; это порядок, который помогает не гадать.

Сегодня намеренно не разбираем `display`, Flexbox, Grid, позиционирование, адаптивность, переменные, методологии и полный алгоритм каскада. Сначала научимся понимать отдельную декларацию.

## 0:08–0:20. Первое правило и его значение

**[Слайд 6 — «Браузер загружает CSS как отдельный ресурс»]**

Исполняемый пример находится в `slides/public/examples/02-css-basics/`. В `head` подключён файл стилей:

```html
<link rel="stylesheet" href="styles.css">
```

`rel="stylesheet"` сообщает браузеру тип связанного ресурса. `href` указывает путь к нему. Когда браузер строит страницу, он находит `link` и загружает CSS отдельным ресурсом.

[Открыть `index.html` и `styles.css` рядом. В DevTools показать, что `styles.css` загружен.]

**[Слайд 7 — «Декларация меняет один аспект поверх базового вида»]**

Компонент сохраняет два столбца: слева одна и та же карточка, справа выбранная декларация. В тексте над карточкой явно перечислены уже существующие базовые стили. Кнопки «Базовый вид» и «С декларацией» позволяют увидеть, что новое правило не создаёт всю карточку, а меняет один аспект поверх основы.

Нажимаем `color`, `font-size`, `background`, `border`, `padding`. Каждый раз читаем правило: селектор выбирает элемент, свойство называет аспект представления, значение задаёт результат. HTML при этом не меняется: заголовок остаётся заголовком, ссылка — ссылкой, карточка — `article`.

**[Слайд 8 — «Свойства принимают значения разных категорий»]**

Значения — не произвольные слова. Уже в нашем небольшом примере встречаются пять категорий:

- ключевое слово: `text-decoration: none`;
- длина: `padding: 20px` или `font-size: 2rem`;
- процент: `width: 100%`;
- цвет: `color: #075985`;
- составное значение: `border: 1px solid #cbd5e1`.

Составное значение — это несколько ожидаемых частей для одного свойства: у `border` здесь толщина, вид линии и цвет. Сейчас достаточно узнавать эти формы, а не запоминать каталог единиц и свойств.

**[Слайд 9 — «Недопустимое значение браузер игнорирует»]**

Сравним две декларации:

```css
h1 {
  font-size: 20px;   /* допустимо */
  font-size: loud;   /* недопустимо — игнорируется */
}
```

`20px` — допустимая длина для `font-size`; `loud` — нет. Браузер не применяет вторую декларацию. Это не означает, что весь CSS-файл сломан: итоговый `font-size` останется `20px` или другим подходящим значением.

[В DevTools выбрать `h1`. В исходной строке DevTools покажет диагностику недопустимого значения; в Computed увидеть итоговые `20px`. Назвать это первым диагностическим шагом до поиска «сильного селектора».]

**[Слайд 10 — «Браузер уже применяет CSS»]**

Даже до нашего файла у заголовка крупный текст, у ссылки синий цвет, у списка отступы. Их задаёт user-agent stylesheet — встроенная таблица стилей браузера. Во вкладке Styles видны применённые правила, зачёркнутые проигравшие объявления и сообщения о недопустимых значениях.

[Выделить `h1`, затем ссылку. Показать правило браузера и правило из `styles.css`.]

**[Слайд 11 — «Стили приходят из трёх источников»]**

У каждого CSS-объявления есть источник, или origin. **Браузер** предоставляет встроенную user-agent stylesheet: благодаря ей заголовок крупнее обычного текста, а ссылка заметна даже без нашего CSS. **Пользователь** может подключить собственную таблицу стилей под свои потребности, например увеличить читаемость интерфейса. **Автор страницы** задаёт правила в подключённых CSS-файлах, элементе `<style>` и атрибуте `style`.

Источник — один из факторов каскада. Обычные авторские объявления обычно переопределяют обычные правила браузера, поэтому наше `h1 { color: #075985; }` меняет базовый вид заголовка. Полный порядок источников и важности здесь не запоминаем: в этой лекции дальше сравниваем обычные авторские объявления, а полный каскад разберём в лекции 5.

[В DevTools у одного элемента показать правило из user-agent stylesheet и правило из `styles.css`. Спросить, кто создал каждое из них.]

**[Слайд 12 — «Три способа подключить CSS»]**

Автор страницы может добавить CSS тремя способами.

**Внешняя таблица стилей** подключается в `<head>`:

```html
<link rel="stylesheet" href="styles.css">
```

`href` задаёт адрес CSS-файла, а `rel="stylesheet"` сообщает браузеру тип связанного ресурса. Это основной способ для проекта: один файл можно подключить к нескольким страницам, кэшировать и редактировать отдельно от HTML.

**Элемент `<style>`** также обычно размещают в `<head>`, но сами правила находятся внутри HTML-документа:

```html
<style>
  h1 { color: #075985; }
</style>
```

Такие правила действуют только в текущем документе. Способ подходит для небольшого автономного примера, но в проекте смешивает структуру и оформление.

**Атрибут `style`** задаёт декларации непосредственно одному элементу:

```html
<h1 style="color: #075985;">Заголовок</h1>
```

Здесь нет селектора: элемент уже выбран самим атрибутом. Такое оформление трудно переиспользовать и переопределять, поэтому для обычной вёрстки предпочитаем внешний CSS-файл.

[Сопоставить три примера на слайде: отдельный ресурс, правила текущего документа, декларации одного элемента. Спросить, какой способ позволит использовать одни правила на нескольких страницах.]

## 0:20–0:35. Селекторы и классы

**[Слайд 13 — «Выбрать все элементы данного типа»]**

Начнём с селектора элемента:

```css
h1 { color: #075985; }
p { color: #334155; }
```

Такое правило выбирает все соответствующие элементы. Это хорошо, когда правило действительно общее: для базового текста, заголовков, ссылок или кнопок.

**[Слайд 14 — «Класс — авторская классификация или крючок»]**

Класс не заменяет HTML. `button.primary-action` остаётся кнопкой, `article.event-card` — статьёй, `a.nav-link` — ссылкой. Класс описывает вариант оформления, выбирает группу элементов или позже связывает код с поведением.

**[Слайд 15 — «Иногда достаточно атрибута или идентификатора»]**

Кроме селектора элемента и класса, полезно знать три простых случая:

```css
* { box-sizing: border-box; }
#registration { scroll-margin-top: 2rem; }
input[required] { border-color: #075985; }
```

`*` — универсальный селектор, `#registration` — селектор идентификатора, `input[required]` — атрибутный селектор. Универсальный селектор применяем осознанно, а идентификатор сохраняем уникальным.

**[Слайд 16 — «Пробел означает „потомок“»]**

`nav a` выбирает ссылки внутри `nav`; `main a` — ссылки внутри `main`. Контекст применяем, когда он действительно определяет роль. Не строим длинные маршруты из всей структуры документа.

**[Слайд 17 — «article.event-card — не article .event-card»]**

Без пробела `article.event-card` означает один и тот же элемент: это `article` и он одновременно имеет класс `event-card`. С пробелом `article .event-card` означает потомка: любой элемент с этим классом внутри статьи.

**[Слайд 18 — «Связать элементы отношением»]**

Комбинатор описывает связь между частями селектора:

```css
nav a { color: #172033; }
article > header { border-bottom: 1px solid #cbd5e1; }
h2 + ol { margin-top: 0.5rem; }
h2 ~ p { color: #475569; }
```

Пробел выбирает любого потомка, `>` — только непосредственного ребёнка, `+` — следующий соседний элемент, `~` — любого последующего соседа.

**[Слайд 19 — «Запятая означает „или“»]**

Запятая означает «или». Все перечисленные элементы получают одно намеренно выбранное правило:

```css
button,
input,
textarea {
  font-size: 1rem;
}
```

[Пауза 4 минуты. Дать HTML с `header`, `nav`, `main`, двумя `article` и `footer`. Попросить написать селекторы для ссылок навигации, `h2` внутри статей и основной кнопки формы.]
**[Слайд 20 — «Что выберет каждый селектор?»]**

Слева HTML-фрагмент Frontend Meetup. На каждом клике подсветка переходит к строкам, подходящим очередному селектору. Проверяем `article`, `.event-card`, `main a` и `.site-nav a`.

Ответ важнее синтаксиса. До написания CSS нужно уметь показать элементы, которые подходят правилу. Если этого нельзя сделать, селектор пока слишком расплывчатый.

## 0:35–0:50. Каскад и наследование

**[Слайд 21 — «Браузер выбирает победителя для каждого свойства»]**

Компонент показывает два правила, которые подходят ссылке `a.nav-link`, и компактный результат Computed. У `a` проигрывает только `color: #0369a1`: он зачёркнут, потому что цвет из `.nav-link` сильнее. Но `text-decoration-thickness: 0.1em` из `a` остаётся итоговым, потому что второе правило не задаёт это свойство.

Каскад — не очередь, в которой более позднее правило выключает прежнее целиком. Браузер выбирает одного победителя **для каждого свойства отдельно**. В DevTools спрашиваем не «какое правило сработало?», а «откуда взялось это свойство?».

**[Слайд 22 — «Сегодня сравниваем обычные авторские объявления»]**

Ограничим модель честно. Сегодня для одного свойства сравниваем **обычные авторские объявления**: сначала специфичность, а если она одинакова — порядок исходного кода. Полный каскад учитывает источники, важность и другие факторы; их соберём в единый алгоритм в лекции 5. Не смешиваем их с сегодняшней рабочей моделью.

**[Слайд 23 — «При равной специфичности побеждает более позднее объявление»]**

```css
.event-card { border-color: #cbd5e1; }
.event-card { border-color: #7dd3fc; }
```

Селекторы одинаковые, поэтому победит объявление ниже. Это порядок исходного кода. Не лечим дубликаты `!important`: сначала выясняем, нужно ли убрать устаревшее правило или дать правилам разные понятные роли.

**[Слайд 24 — «Собственное значение ребёнка важнее унаследованного»]**

```css
body#page { color: #172033; }
a { color: #075985; }
```

`color` обычно наследуется, поэтому без второго правила ссылка получила бы тёмный цвет от `body`. Но `a { color: ... }` задано прямо ссылке, и оно выигрывает у наследования. Здесь не сравниваем специфичность `body#page` и `a`: правило родителя не соревнуется с собственным объявлением ребёнка.

**[Слайд 25 — «Наследование»]**

Некоторые свойства приходят к потомку от родителя, если для потомка нет собственного значения. Обычно это `color` и `font-family`. Обычно не наследуются `margin`, `padding`, `border`, `width` и `background`.

Так удобно один раз задать базовую типографику. Но если у `main` есть рамка, у каждого абзаца внутри не появится такая же рамка.

**[Слайд 26 — «Наследование шрифта лучше выразить явно»]**

Элементы управления могут сохранить браузерный шрифт. Поэтому, если хотим шрифт текста страницы, явно выбираем только это свойство:

```css
button,
input,
textarea,
select {
  font: inherit;
}
```

[Открыть страницу в DevTools. Показать у ссылки правило `a`, правило класса и наследуемый `font-family` от `body`. Затем временно выключить одно объявление флажком в Styles.]

## 0:50–1:03. Специфичность

**[Слайд 27 — «Три уровня для первого приближения»]**

Для первого приближения достаточно трёх уровней: элемент `a`, класс `.nav-link`, идентификатор `#main-menu`. Класс сильнее элемента, идентификатор сильнее класса. Цель не в том, чтобы всегда писать самый сильный селектор, а в том, чтобы причина конфликта была видна.

`id` в HTML чаще нужен для якорной ссылки, связи `label` и `input`, JavaScript или ARIA. Не используем его как главный инструмент CSS только ради высокой специфичности.

**[Слайд 28 — «Сначала id, затем классы, затем элементы»]**

```css
main a {}             /* 0–0–2 */
.site-nav a {}        /* 0–1–1 */
#main-menu a {}       /* 1–0–1 */
```

Сначала сравниваются идентификаторы, затем классы, затем элементы. Поэтому `.site-nav a` сильнее `main a`, а `#main-menu a` сильнее обоих. Это сравнение остаётся в границах обычных авторских объявлений, о которых договорились на слайде 20.

**[Слайд 29 — «Диагностируем конфликт»]**

Если стиль не применился, действуем так:

1. выбираем элемент в DevTools;
2. находим зачёркнутое объявление;
3. смотрим победителя именно для этого свойства, его селектор и порядок;
4. меняем правило или удаляем лишнее.

`!important` меняет порядок каскада и почти всегда делает следующий конфликт сложнее, поэтому не начинаем с него.

**[Слайд 30 — «Какое правило победит?»]**

```css
main a { color: #0369a1; }
.notice a { color: #b45309; }
```

Для ссылки внутри `<main class="notice">` победит `.notice a`: класс делает второй селектор специфичнее. При равной специфичности посмотрели бы на порядок строк.

[Пауза 4 минуты. Дать три правила для ссылки: `a`, `.site-nav a`, `#main-menu a`. Попросить предсказать итоговый цвет, затем проверить в DevTools.]

## 1:03–1:15. Псевдоклассы и состояния

**[Слайд 31 — «Псевдокласс начинается с двоеточия»]**

Пользователь наводит указатель, переходит по ссылке, нажимает кнопку и перемещается Tab. Псевдокласс выбирает элемент в определённом состоянии:

```css
a:hover {}
a:focus-visible {}
button:active {}
input:invalid {}
```

Сегодня подробно разбираем первые три. `:invalid` показывает, что у поля не прошла встроенная проверка браузера; к валидации вернёмся вместе с поведением форм и JavaScript.

**[Слайд 32 — «Состояния можно увидеть и с мышью, и с клавиатурой»]**

Это живая демонстрация, а не картинка. Наведите указатель на кнопку — сработает `:hover`. Нажмите Tab, чтобы перейти к ней — браузер покажет `:focus-visible`. Удерживайте Enter или пробел — видно `:active`. Кнопка нативно доступна с клавиатуры, а её текст подсказывает текущее временное состояние.

Нажатие не сохраняется. CSS только сообщает, что действие происходит сейчас; он не создаёт состояние приложения и не отправляет данные.

**[Слайд 33 — «hover не заменяет focus-visible»]**

```css
a:hover { color: #075985; }

a:focus-visible {
  outline: 3px solid #075985;
  outline-offset: 3px;
}
```

Пользователь с клавиатурой не вызывает `hover`. Поэтому не убираем обводку без заметной замены. Цвет `#075985` имеет контраст с белым фоном выше 3:1 и подходит для этой обводки.

**[Слайд 34 — «Нажмите Tab. Всегда ли видно, где сейчас фокус?»]**

[Открыть пример. Несколько раз нажать Tab. Спросить: «Где сейчас фокус? Видно ли его?» Затем на минуту отключить правило `:focus-visible` и снова пройти страницу с клавиатуры.]

Эту проверку стоит повторять после изменения ссылок, кнопок и полей. Пользователь не обязан пользоваться мышью, чтобы увидеть, где он находится.

## 1:15–1:23. Блочная модель

**[Слайд 35 — «Блочная модель»]**

У каждого элемента есть прямоугольная область. В центре `content`, содержимое. Вокруг него `padding`, внутренний отступ. Затем `border`, граница. Снаружи `margin`, внешний отступ до соседей.

**[Слайд 36 — «У каждой области своё назначение»]**

Схема раскрывается обычными кликами по слайду, без отдельных интерактивных элементов. Сначала подсвечен `content`, затем последовательно `padding`, `border` и `margin`. С каждым шагом связываем название и функцию: место для текста, свободное место внутри, линия границы, расстояние до соседей.

`padding` увеличивает свободное место внутри фона элемента. `border` рисует границу. `margin` отделяет элемент от окружающих блоков.

**[Слайд 37 — «Сокращённые записи читаем по частям»]**

```css
.event-card {
  background: #ffffff;
  border: 1px solid #cbd5e1;
  border-radius: 8px;
  margin: 16px 0;
  padding: 20px;
}
```

Здесь не изучаем большой каталог сокращений, а разбираем только уже используемые. `border: 1px solid #cbd5e1` содержит ширину, вид линии и цвет. В двухзначном `margin: 16px 0` первое значение относится к верху и низу, второе — к левому и правому краю. Одно значение `padding: 20px` действует на все четыре стороны.

Текст не прилипает к рамке из-за `padding`, карточки не слипаются по вертикали из-за `margin`, а фон занимает content и padding, но не margin.

**[Слайд 38 — «content-box и border-box считают по-разному»]**

По умолчанию `content-box` считает `width` шириной только content. Padding и border по краям добавляются к видимому размеру, поэтому `width: 100%` может выйти за ширину родителя.

При `border-box` объявленная ширина включает content, padding и border. Это не делает страницу адаптивной и не располагает элементы; оно лишь делает размер понятнее.

**[Слайд 39 — «Включить padding и border в объявленный размер»]**

```css
*,
*::before,
*::after {
  box-sizing: border-box;
}
```

`*` выбирает все элементы. `::before` и `::after` — будущие декоративные части элементов; правило заранее задаёт им тот же способ расчёта.

**[Слайд 40 — «342 px»]**

Пусть у элемента `width: 300px`, `padding: 20px` слева и справа, граница `1px` слева и справа. При `content-box` видимая ширина: `300 + 20 + 20 + 1 + 1 = 342px`. При `border-box` видимая ширина — `300px`; для content остаётся `258px`.

[Пауза 2 минуты. Дать карточку с `width: 100%`, padding и рамкой. Попросить назвать причину переполнения и исправить только способ расчёта.]

## 1:23–1:30. Проверка и завершение

**[Слайд 41 — «Шесть шагов при отладке CSS»]**

Перед тем как считать CSS «неработающим», идём по запоминаемой последовательности:

1. значение декларации допустимо для свойства?
2. селектор выбирает нужный элемент?
3. не переопределяет ли свойство другое правило?
4. значение пришло от родителя или задано ребёнку?
5. видно ли состояние клавиатурного фокуса, а не только `hover`?
6. как `padding`, `border`, `margin` и `box-sizing` влияют на размер?

**[Слайд 42 — «Назовите первый диагностический шаг»]**

Попросить аудиторию назвать первый шаг, а не сразу готовое свойство:

- `font-size: loud` — проверить допустимость значения в DevTools;
- у ссылки в навигации не тот цвет — проверить селектор, специфичность и порядок правил;
- кнопка выглядит другим шрифтом — проверить наследование или записать `font: inherit`;
- карточка с `width: 100%` создаёт прокрутку — проверить блочную модель и `box-sizing`.

**[Слайд 43 — «Дальше — раскладка страницы»]**

Сегодня CSS научил нас выбирать элемент и менять его свойства предсказуемо. На следующей лекции появится следующий вопрос: как расположить элементы на странице? Для него понадобятся поток документа, `display`, позиционирование, Flexbox и Grid.
