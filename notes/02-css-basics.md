## 0:00–0:07. HTML уже есть — зачем CSS

**[Слайд 1 — «Основы CSS»]**

На прошлой лекции мы построили честный HTML-документ. В нём есть `header`, `nav`, `main`, заголовки, ссылка, форма и кнопка. Если отключить все стили, человек всё равно понимает, где он находится и что может сделать. Это не промежуточная заготовка, а основа страницы.

Сегодня мы не будем заменять эту основу. Мы ответим на другой вопрос: как сделать документ удобнее читать и использовать, не потеряв его смысл?

**[Слайд 2 — «HTML описывает содержание; CSS описывает представление»]**

HTML отвечает: «Это ссылка», «Это основной заголовок», «Это поле формы». CSS отвечает: «Ссылка выглядит так, заголовок имеет такой размер, вокруг карточки есть такое пространство». JavaScript позже ответит: «Что происходит после действия пользователя».

Это разделение важно не только для порядка в файлах. Если у кнопки исчезнет синий фон, она всё ещё останется кнопкой. Если у ссылки изменится цвет, она всё ещё ведёт к ресурсу. А если мы заменим кнопку `div`-ом только потому, что так проще раскрасить, CSS скроет проблему лишь на время.

[Открыть страницу мероприятия из первой лекции. Сначала показать её без подключённого CSS, затем подключить готовый минимальный stylesheet. Спросить: «Что изменилось визуально? Что не изменилось по смыслу?»]

**[Слайд 3 — «Что делает CSS?»]**

CSS — Cascading Style Sheets, каскадные таблицы стилей. Слово *cascading* здесь главное. Браузер редко берёт свойство из одного-единственного правила. Обычно к одному элементу подходят несколько правил: одно задаёт цвет текста, другое — отступ, третье — состояние при фокусе. Браузер должен решить, какие объявления победят.

К концу лекции у нас будет не коллекция свойств на память, а рабочая последовательность вопросов: какой элемент выбрал селектор? Какие правила к нему подходят? Что наследовалось? Какое правило победило? Из чего сложился размер элемента?

**[Слайд 4 — «К концу лекции вы сможете»]**

Сегодня научимся подключать CSS, выбирать элементы селекторами, использовать классы, читать каскад, наследование и специфичность, оформлять состояния `hover` и `focus-visible`, а также считать коробочную модель. Flexbox, Grid, позиционирование и адаптивность намеренно оставим следующей лекции: сначала нужно научиться понимать отдельное правило.

## 0:07–0:17. Первый файл CSS

**[Слайд 5 — «Подключаем внешний stylesheet»]**

Для учебного примера рядом с `index.html` создадим файл `styles.css`:

```text
web-html-intro/
├── index.html
└── styles.css
```

В `head` документа добавим ссылку на этот файл:

```html
<link rel="stylesheet" href="styles.css">
```

`rel="stylesheet"` сообщает браузеру, что это таблица стилей. `href` указывает путь к ней. Когда браузер строит страницу, он загружает HTML, находит `link` и получает ещё один ресурс — CSS.

[Открыть `index.html` и `styles.css` рядом. Сохранить оба файла, обновить браузер. Показать в DevTools Network или Elements, что `styles.css` действительно загружен.]

**[Слайд 6 — «CSS-правило: кого выбрать и что изменить»]**

Напишем первое правило:

```css
body {
  color: #172033;
  font-family: system-ui, sans-serif;
  line-height: 1.5;
}
```

Слева от фигурной скобки — селектор `body`. Он отвечает на вопрос «к кому применить правило?». Внутри — объявления. Каждое объявление состоит из свойства, двоеточия и значения: `color`, `font-family`, `line-height`.

Не надо пока запоминать коды цветов или длинный список шрифтов. Важнее увидеть форму: **селектор выбирает, декларация меняет свойство**. Одно правило можно прочитать вслух так: «Для тела документа установи тёмный цвет текста, системный шрифт и высоту строки полторы».

**[Слайд 7 — «Браузер уже применяет CSS»]**

Даже до нашего файла у заголовка крупный текст, у ссылки синий цвет, у списка отступы. Это не HTML-стили. Браузер поставляет собственную базовую таблицу стилей. Её называют user-agent stylesheet.

Наш CSS обычно переопределяет эти начальные решения. Поэтому полезно не гадать, откуда взялся отступ у `h1`, а открыть DevTools, выбрать элемент и посмотреть вкладку Styles. Там видны применённые правила и зачёркнутые объявления, которые проиграли.

[Открыть DevTools → Elements. Выделить `h1`, затем ссылку. Показать правило браузера и правило из `styles.css`.]

**[Слайд 8 — «Проверка: где ошибка?»]**

Покажем два варианта:

```css
h1 {
  color: #075985;
}
```

```css
h1
  color: #075985;
}
```

В первом варианте есть селектор и блок деклараций. Во втором нет фигурной скобки — браузер не может прочитать правило. CSS обычно не останавливает всю страницу из-за одной ошибки, поэтому опечатка может выглядеть как «ничего не работает». Первый инструмент диагностики — DevTools, второй — внимательно прочитать структуру правила.

## 0:17–0:32. Селекторы и классы

**[Слайд 9 — «Селектор выбирает элементы»]**

Начнём с селектора элемента:

```css
h1 {
  color: #075985;
}

p {
  color: #334155;
}
```

Такое правило выбирает все соответствующие элементы на странице. Это хорошо, когда правило действительно общее: например, для базового текста, заголовков, ссылок или кнопок.

Но не всякая ссылка должна выглядеть одинаково. Ссылка в навигации может быть компактной, а ссылка в тексте — подчёркнутой. Для устойчивой визуальной роли добавляют класс:

```html
<a class="site-nav__link" href="#program">Программа</a>
```

```css
.site-nav__link {
  color: #172033;
  text-decoration: none;
}
```

Точка в CSS означает «класс». Имя класса — договор автора кода с самим собой: этот элемент играет конкретную визуальную роль.

**[Слайд 10 — «Класс дополняет семантику»]**

Класс не заменяет HTML-элемент. Правильно: `button class="primary-action"`, потому что элемент остаётся кнопкой, а класс описывает оформление основной операции. Правильно: `article class="event-card"`, потому что материал остаётся статьёй, а класс описывает карточку.

Плохо строить страницу из `<div class="button">` и `<div class="link">`. CSS сможет нарисовать знакомый вид, но браузер не узнает поведение и назначение элементов. Смысл выбираем HTML, вариант оформления — классом.

**[Слайд 11 — «Селектор в контексте»]**

Можно выбрать элемент внутри другой области:

```css
nav a {
  color: #172033;
}

main a {
  color: #0369a1;
}
```

Пробел означает «потомок». `nav a` выбирает ссылки, находящиеся внутри `nav`; `main a` — ссылки внутри `main`. Такой селектор полезен, когда контекст действительно определяет роль элемента.

Но не нужно превращать каждый селектор в длинный маршрут по документу:

```css
body main article .event-card h2 {
  color: #075985;
}
```

Это правило зависит от слишком многих деталей структуры. Если `article` появится внутри другого контейнера, оформление неожиданно исчезнет. Начинаем с самого короткого селектора, который выражает задачу.

**[Слайд 12 — «Список и сочетание селекторов»]**

Один набор деклараций может подойти нескольким селекторам:

```css
button,
input,
textarea {
  font: inherit;
}
```

Запятая означает «или». Здесь мы говорим: все перечисленные элементы должны использовать шрифт текста страницы. Это отдельное правило для формы, а не случайная попытка исправить вид браузера.

Селекторами сегодня решаем одну задачу: точно выбрать нужные элементы. Не пытаемся сразу расположить блоки по сетке или в ряд. Их расположение станет отдельной темой лекции 3.

[Пауза 4 минуты. Дать HTML с `header`, `nav`, `main`, двумя `article` и `footer`. Попросить написать селекторы для всех ссылок навигации, всех `h2` внутри статей и только основной кнопки формы. После этого разобрать, где элементный селектор, где класс, а где контекст.]

**[Слайд 13 — «Проверка: что выберет селектор?»]**

Спросить: что выберет каждый селектор?

```css
article {}
.event-card {}
main a {}
.site-nav a {}
```

Ответ важнее синтаксиса. Перед написанием CSS нужно уметь пальцем показать элементы, которые подходят правилу. Если этого нельзя сделать, селектор пока слишком расплывчатый.

## 0:32–0:45. Каскад и наследование

**[Слайд 14 — «К одному элементу подходит несколько правил»]**

Посмотрим на ссылку:

```css
a {
  color: #0369a1;
  text-decoration-thickness: 0.1em;
}

.site-nav__link {
  color: #172033;
  text-decoration: none;
}
```

Оба правила подходят ссылке с классом `site-nav__link`. Это не ошибка. Итоговый стиль собирается из обоих: `text-decoration-thickness` приходит из правила `a`, `color` и `text-decoration` — из правила класса.

Каскад — не очередь, где второе правило отменяет первое целиком. Браузер выбирает победителя **для каждого свойства отдельно**. Поэтому в DevTools полезно смотреть не «какое правило сработало», а «откуда взялось это свойство».

**[Слайд 15 — «Если значения равны — побеждает более позднее правило»]**

Теперь два правила меняют одно свойство с одинаковой силой:

```css
.event-card {
  border-color: #cbd5e1;
}

.event-card {
  border-color: #7dd3fc;
}
```

Оба селектора одинаковые. Значит, победит объявление, написанное ниже. Это порядок исходного кода. Он удобен для осознанного уточнения стиля, но превращается в хаос, если файл растёт без структуры и одно правило случайно дублирует другое.

Не надо лечить такой конфликт `!important`. Сначала выясняем: оба правила нужны? Если нет — удаляем устаревшее. Если нужны — делаем их роли понятными: например, одно отвечает за базовую карточку, другое — за её специальное состояние.

**[Слайд 16 — «Наследование: свойство приходит от родителя»]**

Некоторые свойства потомки получают от родителя. Например:

```css
body {
  color: #172033;
  font-family: system-ui, sans-serif;
}
```

Текст внутри `main`, `p`, `li` и многих других элементов получит этот цвет и шрифт, если не задано более конкретное значение. Так удобно задавать базовую типографику один раз.

Но не всё наследуется. `margin`, `padding`, `border`, `width` и `background` обычно не переходят к детям. Если у `main` есть рамка, у каждого абзаца внутри не появится такая же рамка. Это помогает не ожидать от CSS невозможного.

**[Слайд 17 — «Наследование формы нужно проверить»]**

Элементы управления формой имеют стили браузера. Шрифт у кнопки или поля может отличаться от текста страницы, даже если мы задали шрифт для `body`. Поэтому часто явно пишут:

```css
button,
input,
textarea,
select {
  font: inherit;
}
```

Это не универсальный сброс всех стилей. Мы выбираем одно конкретное свойство, которое хотим унаследовать, и записываем намерение явно.

[Открыть страницу в DevTools. Показать у ссылки одновременно правило `a`, правило класса и наследуемый `font-family` от `body`. Затем временно выключить одно объявление флажком в панели Styles.]

## 0:45–0:57. Специфичность

**[Слайд 18 — «Почему правило не применилось?»]**

Самая частая формулировка проблемы звучит так: «Я задал цвет, а он не поменялся». На самом деле браузер не игнорирует CSS. Чаще всего другое правило выбрало тот же элемент и оказалось сильнее.

Сравним:

```css
a {
  color: #0369a1;
}

.site-nav__link {
  color: #172033;
}
```

Класс точнее, чем имя элемента, поэтому при конфликте `color` у ссылки с классом победит `.site-nav__link`. Это и есть специфичность: способ сравнить, какое из подходящих правил точнее описывает элемент.

**[Слайд 19 — «Элемент, класс, идентификатор»]**

Для первого приближения достаточно помнить три уровня:

```css
a {}               /* элемент */
.site-nav__link {} /* класс */
#main-menu {}      /* идентификатор */
```

Класс сильнее элемента. Идентификатор сильнее класса. Но цель не в том, чтобы каждый раз выиграть соревнование самым сильным селектором. Цель — писать правила так, чтобы конфликтов было мало и их причина была видна.

Идентификатор `id` в HTML чаще нужен для якорной ссылки, связи `label` и `input`, JavaScript или ARIA. Не стоит брать его как основной инструмент CSS только ради высокой специфичности.

**[Слайд 20 — «Как читать специфичность»]**

Можно представить селектор как три счётчика: идентификаторы, классы и элементы. Сначала сравниваются идентификаторы, затем классы, затем элементы.

```css
main a {}             /* 0–0–2 */
.site-nav a {}        /* 0–1–1 */
#main-menu a {}       /* 1–0–1 */
```

Поэтому `.site-nav a` сильнее `main a`: у первого есть класс. Но `#main-menu a` сильнее обоих: у него есть идентификатор. Записывать числа вручную на каждом проекте не требуется; схема нужна, чтобы перестать угадывать.

**[Слайд 21 — «Не начинаем с `!important`»]**

`!important` меняет порядок каскада и почти всегда делает следующий конфликт сложнее. Если стиль не применился, действуем иначе:

1. выбираем элемент в DevTools;
2. находим зачёркнутое объявление;
3. смотрим, какое правило победило;
4. решаем, нужно ли изменить селектор, порядок правил или удалить лишнее правило.

[Пауза 5 минут. Дать три правила для ссылки: `a`, `.site-nav a`, `#main-menu a`. Попросить предсказать итоговый цвет, затем проверить в DevTools. Во втором примере дважды записать `.event-card` и найти победителя по порядку исходного кода.]

**[Слайд 22 — «Проверка: какое правило победит?»]**

Спросить перед ответом браузера:

```css
main a { color: #0369a1; }
.notice a { color: #b45309; }
```

Для ссылки внутри `<main class="notice">` победит `.notice a`: класс делает это правило специфичнее. Если бы оба селектора имели одинаковую специфичность, смотрели бы на порядок строк в файле.

## 0:57–1:10. Псевдоклассы и состояния

**[Слайд 23 — «У элемента есть состояние»]**

Страница не состоит из неподвижных карточек. Пользователь наводит указатель, переходит по ссылке, нажимает кнопку, вводит текст, перемещается клавишей Tab. В каждом состоянии элемент может требовать другого оформления.

Псевдокласс начинается с двоеточия и выбирает элемент в определённом состоянии:

```css
a:hover {}
a:focus-visible {}
button:active {}
input:invalid {}
```

Сегодня возьмём первые три. Валидацию форм подробнее разберём вместе с поведением и JavaScript; сейчас важно увидеть сам принцип.

**[Слайд 24 — «`hover` не заменяет `focus-visible`»]**

Ссылка в тексте может выглядеть так:

```css
a {
  color: #0369a1;
}

a:hover {
  color: #075985;
}

a:focus-visible {
  outline: 3px solid #f59e0b;
  outline-offset: 3px;
}
```

`:hover` работает для указателя. Человек с клавиатурой его не вызывает. `:focus-visible` показывает, на каком элементе сейчас находится фокус, когда такое указание нужно пользователю. Не убираем `outline`, пока не дали ему заметную замену.

**[Слайд 25 — «Кнопка сообщает нажатие»]**

У кнопки можно показать момент нажатия:

```css
button:active {
  background: #0c4a6e;
}
```

Это только небольшая визуальная реакция. Она не сохраняет данные и не отправляет форму. Помним распределение ролей: CSS показывает состояние, JavaScript позже будет менять состояние приложения, а HTML сохраняет назначение кнопки.

Оформление состояния должно объяснять интерфейс, а не требовать от человека внимания к каждому эффекту.

**[Слайд 26 — «Проверка: доступен ли фокус?»]**

## 1:10–1:22. Box model

**[Слайд 27 — «Каждый элемент — коробка»]**

Когда мы говорим «добавить отступ», нужно уточнить: отступ где? У каждого элемента есть прямоугольная коробка. В центре — content, содержимое. Вокруг него — padding, внутренний отступ. Затем border, рамка. Снаружи — margin, внешний отступ до соседей.

```text
margin
  border
    padding
      content
```

Это не четыре названия одного и того же расстояния. `padding` увеличивает свободное место внутри фона элемента. `border` рисует границу. `margin` отделяет элемент от окружающих блоков.

**[Слайд 28 — «Внутри, на границе, снаружи»]**

Оформим карточку мероприятия:

```css
.event-card {
  background: #ffffff;
  border: 1px solid #cbd5e1;
  border-radius: 8px;
  margin: 16px 0;
  padding: 20px;
}
```

Текст не прилипает к рамке из-за `padding`. Карточки не слипаются по вертикали из-за `margin`. Рамка видна благодаря `border`. Цвет фона занимает content и padding, но не margin.

[Выделить карточку в DevTools. Открыть вкладку Computed и показать интерактивную схему box model. Навести на content, padding, border и margin, чтобы браузер подсветил каждую область.]

**[Слайд 29 — «Почему `width: 100%` иногда выходит за пределы?»]**

По умолчанию CSS использует модель `content-box`. Если написать:

```css
.event-card {
  width: 100%;
  padding: 20px;
  border: 1px solid #cbd5e1;
}
```

то `width` задаёт ширину только content. Слева и справа к ней добавляются `padding` и `border`. Поэтому видимая коробка может оказаться шире родителя.

Для предсказуемого расчёта часто используют:

```css
*,
*::before,
*::after {
  box-sizing: border-box;
}
```

С `border-box` объявленная ширина включает content, padding и border. Это не делает страницу адаптивной автоматически и не раскладывает блоки по местам. Оно лишь делает размер самой коробки понятнее.

**[Слайд 30 — «Проверка: из чего сложился размер?»]**

Пусть у элемента `width: 300px`, `padding: 20px` слева и справа, граница `1px` слева и справа.

- При `content-box` видимая ширина: `300 + 20 + 20 + 1 + 1 = 342px`.
- При `border-box` видимая ширина: `300px`; внутри неё остаётся `258px` для content.

Точное вычисление нужно не ради арифметики. Оно помогает понять, почему элемент вышел за контейнер, почему тексту тесно и почему изменение `padding` поменяло размер карточки.

[Пауза 3 минуты. Дать карточку с `width: 100%`, `padding` и рамкой. Попросить найти причину горизонтального переполнения и исправить только модель расчёта, не уменьшая отступы наугад.]

## 1:22–1:30. Проверка и завершение

**[Слайд 31 — «Пять вопросов к CSS-правилу»]**

Перед тем как считать CSS «неработающим», задаём пять вопросов:

1. Этот селектор вообще выбирает нужный элемент?
2. Не переопределяет ли нужное свойство другое правило?
3. Свойство наследуется или его нужно задать непосредственно элементу?
4. Видно ли состояние клавиатурного фокуса, а не только `hover`?
5. Как `padding`, `border`, `margin` и `box-sizing` влияют на размер коробки?

Если отвечать на них по порядку, DevTools превращается из случайного набора панелей в инструмент расследования.

**[Слайд 32 — «Мини-проверка»]**

- карточка с `width: 100%` создаёт горизонтальную прокрутку.

В первом случае проверяем селекторы, специфичность и порядок правил. Во втором — наследование свойства `font` или явное `font: inherit`. В третьем — box model и `box-sizing`.

**[Слайд 33 — «Дальше — раскладка страницы»]**

Сегодня CSS научил нас выбирать элемент и менять его свойства предсказуемо. На следующей лекции появится следующий вопрос: как расположить эти коробки на странице? Для него понадобятся поток документа, `display`, позиционирование, Flexbox и Grid.

HTML из первой лекции остаётся фундаментом. CSS из этой лекции добавляет читаемость, иерархию, состояние и пространство. Если смысл документа пропадёт после отключения CSS, проблема всё ещё в HTML. Если смысл сохранится, а визуальный результат неожиданен, теперь есть способ разобрать CSS шаг за шагом.
