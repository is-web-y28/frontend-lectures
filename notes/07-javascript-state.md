## Подготовка

Из корня выполнить `npm ci`, затем `npm run dev:07`. Отдельный backend или сборщик учебных модулей не нужен: iframe загружает ES-модули из `slides/public/examples/07-javascript-state/` по HTTP. До занятия открыть основной пример отдельно и проверить доступность клавиатуры, localStorage и вывода состояния. Если окружение блокирует storage, это отдельный наблюдаемый отказ, а не основание обещать сохранение.

Режим `state` никогда не обращается к storage. Режимы `storage` и `full` сохраняют только обычные записи заявок. «Начать заново» пересоздаёт iframe, но не удаляет сохранение. Для чистого persistent-показа использовать «Очистить сохранение» → «Перезагрузить» → «Три заявки». Очищается только учебный ключ; `localStorage.clear()` не нужен.

## Данные и отображение

Во вступлении оставить Анну, Бориса и Веру. Перед вводом `анна` спросить, исчезнут ли две другие заявки из данных. В источнике остаются три; «Снять фильтр» возвращает все строки и фокус в поиск. Так отделяем полную коллекцию от её изображения.

В первой главе не объединять всю новую запись в один прыжок. Сначала назвать `id`, затем проверку количества, spread, callback, `filter`, деструктуризацию и поиск позиции. `id` не меняется при фильтрации; позиция видимой строки меняется. `filter` не удаляет запись из исходного массива. Удаление проверяет `findIndex` на `-1`, затем создаёт следующую коллекцию.

На слайде «Добавление, поиск и удаление проходят один цикл» добавить Глеба, отфильтровать Бориса и удалить именно его. Попросить назвать полное и видимое количество до действия, затем сверить источник. Правильное объяснение называет изменение данных и последующий `render`, а не исчезновение DOM-строки.

## Граница коллекции и получатель метода

Сначала сравнить новый массив с новыми объектами внутри него. `[...records]` копирует контейнер, но сохраняет ссылки на записи; `map(copyRecord)` отделяет плоские записи. Вложенные значения потребовали бы отдельного решения. Именно из этой проблемы возникает API фабрики, который выдаёт операции и снимки.

В демо замыкания нажимать «Добавить в A» и «Добавить в B» по отдельности, наблюдая два независимых счётчика. Это два вызова одной фабрики с разными переменными, а не глобальный счётчик, который переключает имя. Операции одной фабрики обращаются к одной сохранённой переменной.

У класса сначала «Сравнить функции», затем `first.getAll()` и `second.getAll()`. Равенство методов не означает равенство данных: получатель вызова задаёт `this`. В следующем стенде сравнить обычный метод, отдельную функцию, обёртку и `bind`. Перед каждым вызовом спросить, откуда будет взят получатель. Класс служит сравнением; работающая регистрация продолжает использовать фабрику, а не второй параллельный store.

## Модули и сохранение

Разделение на файлы закрепляет уже установленные обязанности: `state` владеет коллекцией, `view` строит DOM, `main` связывает события. `export` делает имя доступным, `import` получает это имя, а `type="module"` запускает граф от HTML. Перенос файла сам по себе не создаёт новый экземпляр состояния.

После добавления заявки в режиме `state` перезагрузить страницу: память потеряна. Только теперь вводим формат JSON и строковое хранилище. JSON не переносит методы, замыкания и все возможные значения языка; сохраняем проверенные обычные записи. Поиск не должен записывать отфильтрованную коллекцию поверх полного списка.

В режиме `storage` подготовить чистый ключ, добавить заявку и нажать «Перезагрузить»: сохранённая запись возвращается. Затем «Повредить JSON» → «Перезагрузить». Чтение не удалось; после изменения в памяти повреждённая строка не затирается. «Неверная структура» показывает другой случай: JSON синтаксически разбирается, но значение не соответствует массиву заявок. Отличаем парсинг от проверки полей и идентичности.

«Очистить сохранение» удаляет только сохранённую строку и снимает запрет будущих записей; текущая память остаётся. Следующее успешное добавление или удаление может сохранить полный снимок. «Изолированная проба квоты» использует отдельный временный ключ и не заменяет заявки. Нельзя обещать одинаковую квоту или непременный отказ на каждом браузере: обсуждаем фактический статус и сохранность основного ключа.

## Общий сценарий и диагностика

Слайд 68: «Очистить сохранение» → «Перезагрузить» → «Три заявки». Добавить Глеба / gleb@example.com / 3: четыре записи. Найти `boris`: одна из четырёх. Сфокусировать «Удалить Борис» и нажать Space: ноль из трёх, Борис удалён по `id`, фокус возвращён в имя. Снять фильтр и перезагрузить: Анна, Вера и Глеб восстановлены, запрос пуст.

Перед каждым действием получить прогноз. После сценария спросить, где находился полный массив, что меняло его, кто строил DOM и где проходила проверка внешней строки. Успех локального сохранения не означает серверную регистрацию или согласованность нескольких вкладок.

При репетиции фиксировать отметки после глав с учётом ввода и ответов аудитории. Если блок запаздывает, убрать повторный запуск с уже объяснённым результатом; не пропускать объяснение `this`, проверку JSON или защиту после ошибки чтения. Для каждого содержательного слайда готовое объяснение остаётся в slide-local notes; этот сценарий задаёт маршрут и порядок действий, а не заменяет их.

Приложения выбираются независимо: A — возможности языка; B — копии и формат данных; C — миграция и другие вкладки; D — IndexedDB. Ни один раздел не нужен для завершения слайда 68. IndexedDB-опыты используют отдельную базу приложения, а успех запроса не подменяет успех транзакции.
