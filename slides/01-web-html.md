---
layout: "code-explain"
kicker: "Ресурсы документа"
title: "Один путь — четыре разных назначения"
notes:
  - "<code>./</code> начинается рядом с текущим HTML-файлом."
  - "<code>../</code> поднимается на уровень выше."
  - "<code>/</code> начинается от корня сайта; <code>#</code> ищет место в документе."
---
```html {1|2|3|4|all}
<!-- В head -->
<link rel="stylesheet" href="./styles/site.css">

<!-- В body -->
<a href="../index.html">На главную</a>
<img src="/images/logo.svg" alt="Логотип Meetup">
<a href="#registration">К регистрации</a>
```
<!--
Каждая строка — корректный фрагмент в своём месте: link подключают в head, ссылки и изображение помещают в body. `./styles/site.css` ищется рядом с текущим HTML, `../index.html` — на уровень выше, `/images/logo.svg` — от корня сайта, независимо от текущей папки.

`#registration` не ресурс и не папка: это фрагмент, поэтому в документе нужен `id="registration"`. Попросить студентов предсказать, что изменится после переноса HTML-файла в папку.
-->

```html
<link rel="stylesheet" href="./styles/site.css">
```

::right::

```css
/* styles/site.css */
.logo { background: url("./logo.svg"); }
```
<!--
Здесь HTML ищет `styles/site.css` рядом с HTML-документом. Но после загрузки CSS его `url("./logo.svg")` считается уже относительно папки `styles`, то есть ищет `styles/logo.svg`.

Это только правило путей, не урок CSS: оформление, селекторы и свойства разберём на следующей лекции. Связка помогает заранее объяснить распространённый 404 у фоновых картинок.
