<!--
Представьте коробки, вложенные одна в другую. Открыли абзац, внутри выделили слово — значит, закрывать будем в обратном порядке.

Браузер попытается угадать намерение автора, но угадывание — плохая основа для поддержки кода.

Есть элементы без содержимого: `meta` сообщает метаданные, `link` подключает внешний ресурс, `img` вставляет изображение. Их называют пустыми, или void, elements. У них нет пары `</img>` или `</meta>`.

И ещё одна ловушка для новичка: пять пробелов в обычном тексте не сделают пять пробелов на странице. Браузер обычно свернёт их в один. Отступы в HTML помогают человеку видеть вложенность; за размещение элементов отвечает CSS.

Запомним фразу, которая будет возвращаться всю лекцию: HTML не рисует команды «крупнее» и «правее». HTML называет части документа.

<!--
Вернёмся к `index.html`. У него есть служебная часть для браузера и содержательная часть для человека.

`<!doctype html>` включает современный режим браузера. `html` — корень документа. `lang="ru"` сообщает основной язык: программе чтения с экрана проще выбрать произношение, а браузеру и инструментам — правила обработки текста.

`head` — не «невидимый мусор», а паспорт документа. Здесь кодировка, название вкладки, настройки отображения на мобильном экране и связи с ресурсами. `meta charset="utf-8"` помогает корректно прочитать русский текст и другие символы. `meta name="viewport"` — нормальная часть современного шаблона для мобильных экранов.

`title` — название вкладки, истории и закладки. Сравните «Главная» и «Программа Frontend Meetup». Второй вариант помогает человеку вернуться к странице через неделю, когда открыто двадцать вкладок.

`body` — то, что пользователь видит и с чем взаимодействует: заголовки, текст, ссылки, формы, изображения и другие части содержания.
Обновить страницу и специально проверить: изменилось название вкладки, а не заголовок в теле страницы.

Редактор умеет создать этот каркас автоматически. Это удобно. Но шаблон полезен только тогда, когда мы понимаем, какую задачу решает каждая строка.

Теперь у каждого фрагмента есть назначение — а значит, можно выбирать HTML. `header` подходит для вводной части. `nav` — для заметного набора ссылок. `main` выделяет уникальное основное содержание, и обычно на странице он один.

Внутри `main` самостоятельный материал — статья, карточка события, новость — может быть `article`. Отдельная тема с собственным заголовком — `section`: например, «Программа» и «Регистрация». `aside` хранит вспомогательную информацию: совет, предупреждение, справку. `footer` завершает документ контактами, юридическими сведениями или дополнительной навигацией.

Внешне `section` и `div` могут быть одинаковыми. Без CSS оба могут не выглядеть никак. Но `section` говорит: «здесь отдельная тема», а `div` ничего такого не утверждает. Поэтому `div` — техническая группировка, когда специального смысла действительно нет.

Перед выбором элемента задаём себе вопросы в таком порядке: это основной материал или дополнение? Может ли фрагмент существовать отдельно? Есть ли здесь своя тема и заголовок? И только потом — нужен ли нейтральный `div`.
