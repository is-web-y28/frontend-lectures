kicker: Строгий режим
title: Строгий режим превращает <em>часть тихих ошибок в явные</em>
notes:
  - "<code>'use strict'</code> стоит в начале файла или тела функции."
  - "Необъявленное имя даёт <code>ReferenceError</code>, а не глобальную переменную."
  - "Запись в свойство только для чтения даёт <code>TypeError</code>."
  - "Строгий режим не проверяет типы и не исправляет логику программы."
---
```js
'use strict';

total = 45; // ReferenceError: total не объявлен
```
<!--
Представим, что имя total ещё нигде не объявлено. В нестрогом старом скрипте такое присваивание могло незаметно создать глобальное свойство. Код продолжал бы работу, а случайное имя становилось доступно чужому коду. С директивой use strict строка останавливается на ReferenceError там, где допущена ошибка.

Директива должна быть в начале файла или тела функции, до обычных операторов; комментарии перед ней допустимы. Она действует на этот код, а не на все соседние скрипты страницы. В нашем main.js она уже первая строка; демонстрационную ошибку в рабочем файле не оставляем. Строгий режим также превращает запись в свойство только для чтения в TypeError вместо молчаливого игнорирования. Это не то же самое, что const: const защищает связь имени со значением.

Это не система статической типизации и не проверка предметного правила. Он не превратит строку «2» в число и не решит, допустима ли заявка. Дальше нас интересуют имена и значения, с которыми JavaScript действительно работает.
-->

layout: code-explain
kicker: Имена в JavaScript
title: let и const имеют блочную область и <em>не доступны до объявления</em>
notes:
  - "Оба имени видны только внутри своего блока."
  - "Обращение до объявления попадает в temporal dead zone и даёт ReferenceError."
  - "<code>var</code> сегодня не вводим: новый код строим на <code>const</code> и <code>let</code>."
---
```js
{
  console.log(room); // ReferenceError: TDZ
  const room = 'Главный зал';

  let occupied = false;
  occupied = true;
}
```
<!--
Синтаксис знаком, но два свойства важны именно при переходе в JavaScript. И const, и let имеют блочную область: имя существует для нашего кода только внутри ближайших фигурных скобок. Это помогает не делать временную переменную доступной всей функции или файлу.

До строки объявления имя находится в temporal dead zone. Вызов console.log(room) не даст специальное «пустое значение» и не прочитает будущую переменную: он выбросит ReferenceError. Объявление нужно поставить до первого использования. Это правило касается и let, и const.

Для неизменяемого имени начинаем с const; let выбираем, когда алгоритм действительно переприсваивает имя, как occupied выше. var намеренно не вводим: для нового кода у нас нет причины строить привычки вокруг его другой области видимости и поднятия объявления. Теперь уточним: const защищает именно связь имени со значением, а не внутренность объекта.
-->

В talk хранится ссылка на объект. const запрещает присвоить этому имени другую ссылку или другое значение, поэтому закомментированная строка закончится TypeError. Но первая операция меняет свойство того же объекта и потому допустима.

layout: code-explain
kicker: Динамические значения
title: Тип принадлежит значению, а не имени
notes:
  - "<code>typeof</code> наблюдает тип текущего значения."
  - "Одно имя с <code>let</code> может получить значения разных типов."
  - "Динамичность не отменяет необходимость явно проверять данные на границе программы."
---
```js
let attendeeCount = '2';
console.log(typeof attendeeCount); // 'string'

attendeeCount = 2;
console.log(typeof attendeeCount); // 'number'
```
<!--
В C++, C# или Java имя обычно объявляется с типом и не может затем получить значение другого типа без явной другой конструкции. В JavaScript let создаёт имя, а typeof показывает тип значения, лежащего в нём сейчас. Сначала attendeeCount содержит строку, затем — число.

Это не повод относиться к типам как к необязательной детали. Операции выбирают поведение по фактическим значениям: строка плюс число может склеить текст, а число плюс число сложится. На границе браузера — у поля, атрибута, URL или сетевого ответа — нужно наблюдать вход и делать нужное преобразование или проверку явно.

Дальше увидим два частых источника неверных ожиданий: JavaScript не разделяет обычные числа на int и double, а специальное NaN всё равно относится к числам.
-->

<!--
Обычные числовые значения JavaScript представлены типом number: отдельного повседневного int и double, как в некоторых знакомых языках, здесь нет. Это число двойной точности с двоичным представлением. Поэтому 0.1 и 0.2 не обязаны представляться точно, и проверка 0.1 + 0.2 === 0.3 возвращает false.

Не делаем из этого правила запрет на вычисления. Минуты докладов — целые небольшие числа, и их сложение здесь надёжно. Но денежные дроби, измерения и сравнения результатов требуют выбранного для задачи способа представления и допуска, а не ожидания математической идеальности.

NaN возникает, например, при Number('не число'). Несмотря на имя, typeof NaN даёт number: это специальное числовое значение, а не строка и не исключение. Проверяем его Number.isNaN, а не сравнением NaN === NaN. Для границы формы важно не спутать ещё и два вида отсутствия значения.
-->

<!--
[Открыть демонстрацию DOM отдельно и начать заново: в программе два пункта, HTML и CSS. Выполнить показанный фрагмент в Console этой страницы. Перед запуском спросить, изменится ли items.length после append.]

Здесь важно не научиться писать цикл, а понять контракт API. querySelector возвращает одну ссылку на Element либо null. querySelectorAll возвращает NodeList найденных узлов; этот результат статический. В items сохраняются два исходных пункта, хотя append уже добавил третий в реальное дерево. Поэтому первый вывод — 2, а повторный поиск возвращает коллекцию с длиной 3. Если выполнить тот же фрагмент ещё раз без сброса, начальные количества будут другими: комментарии относятся к названному исходному состоянию.

Статический снимок — не копия самих элементов. Ссылки внутри items указывают на реальные узлы: изменение их textContent будет видно на странице. Но новый узел не допишется в старую коллекцию автоматически. NodeList можно обойти знакомым for...of, однако это не обычный Array с полным набором его методов. Не переносите это правило на все DOM-коллекции: некоторые другие API возвращают живые коллекции.

Так мы различили набор ссылок и текущее дерево. Следующий вопрос — что происходит, когда строка из поля становится содержимым найденного или нового узла. Знание обычных строк ещё не защищает от случайного разбора пользовательского текста как HTML.

Мы нашли кнопку и объявили функцию, но пользователь ещё ничего не сделал. addEventListener связывает выбранный элемент, название события и функцию.
```js
const panel =
  document.querySelector('#event-details')

function handleToggle(event) {
  const button = event.currentTarget
  const expanded =
    button.getAttribute('aria-expanded')
      === 'true'
  const nextExpanded = !expanded

  button.setAttribute(
    'aria-expanded', String(nextExpanded),
  )
  panel.hidden = !nextExpanded
}
```
<!--
Мы вернулись к незавершённому примеру пятой лекции. В исходном HTML у кнопки aria-expanded="false", у панели event-details стоит hidden, а aria-controls указывает её ID. CSS может выделить раскрытую кнопку, но не выполнит этот обработчик за нас.

title: target может быть иконкой; <em>closest находит кнопку</em>
notes:
  - "Слушатель установлен на существующем контейнере."
  - "closest находит управляющую кнопку; contains проверяет принадлежность."
  - "toggleDisclosure согласует ARIA и видимость панели."
---
```js
const cards = document.querySelector(
  '#delegated-cards',
)
cards.addEventListener('click', (event) => {
  if (!(event.target instanceof Element)) return
  const button = event.target.closest(
    '.event-toggle',
  )
  if (!button || !cards.contains(button)) return
  toggleDisclosure(button)
})
```
<!--
Этот факультативный слайд объясняет наблюдение, а не вводит ещё одну демонстрацию. cards — существующий #delegated-cards; слушатель продолжает получать всплывающие click от потомков, добавленных позже. В event.target при клике по знаку ⓘ находится span. Проверка Element позволяет вызвать closest, а closest('.event-toggle') находит кнопку по пути к предкам.

Если кнопки нет или она вне дерева cards, менять нечего. Проверка contains задаёт внешнюю границу контейнера, но не фильтрует отдельно вложенные компоненты внутри него. В нашем изолированном дереве каждой кнопке соответствует панель по уникальному aria-controls.

toggleDisclosure(button) — та же функция изменения DOM, которую вызывает прямой слушатель: она читает aria-expanded выбранной кнопки, вычисляет следующее состояние, согласует его с hidden связанной панели и обновляет наблюдение. В делегированном варианте меняется способ найти управляющую кнопку, а не правило раскрытия. Здесь сокращён только журнал события; сама функция используется живой демонстрацией.
