```css
.event-card {

  padding: 20px;
  color: #075985;
  border: 1px solid #cbd5e1;
}
```

<!--
Значение — не произвольное слово, а допустимая форма для конкретного свойства. Здесь `width` получает процент, `padding` — длину, `color` — цвет, а `border` — составное значение из толщины, вида линии и цвета.

  - { term: Пользователь, desc: Пользовательская таблица стилей для собственных потребностей }

<!--
У каждого CSS-объявления есть источник, или origin. **Браузер** предоставляет встроенную user-agent stylesheet: благодаря ей заголовок крупнее обычного текста, а ссылка заметна даже без нашего CSS. **Пользователь** может подключить собственную таблицу стилей под свои потребности, например увеличить читаемость интерфейса. **Автор страницы** задаёт правила в подключённых CSS-файлах, элементе `<style>` и атрибуте `style`.

Источник — один из факторов каскада. Обычные авторские объявления обычно переопределяют обычные правила браузера, поэтому наше `h1 { color: #075985; }` меняет базовый вид заголовка. Полный порядок источников и важности здесь не запоминаем: в этой лекции дальше сравниваем обычные авторские объявления, а полный каскад разберём в лекции 5.

В DevTools у одного элемента покажите правило из user-agent stylesheet и правило из `styles.css`. Спросите, кто создал каждое из них.
-->
---
layout: code-explain
kicker: Авторские стили
title: Три способа подключить CSS
notes:
  - "Внешний файл: <code>&lt;link rel=&quot;stylesheet&quot;&gt;</code> — основной способ"
  - "<code>&lt;style&gt;</code>: правила только для текущего HTML-документа"
  - "Атрибут <code>style</code>: декларации только для одного элемента"
---
```html
<!-- Внешний файл -->
<link rel="stylesheet" href="styles.css">

<!-- Внутри документа -->
<style>
  h1 { color: #075985; }
</style>

<!-- У одного элемента -->
<h1 style="color: #075985;">Заголовок</h1>
```
<!--
Автор страницы может добавить CSS тремя способами.

**Внешняя таблица стилей** подключается в `<head>`. `href` задаёт адрес CSS-файла, а `rel="stylesheet"` сообщает браузеру тип связанного ресурса. Это основной способ для проекта: один файл можно подключить к нескольким страницам, кэшировать и редактировать отдельно от HTML.

**Элемент `<style>`** также обычно размещают в `<head>`, но сами правила находятся внутри HTML-документа. Такие правила действуют только в текущем документе. Способ подходит для небольшого автономного примера, но в проекте смешивает структуру и оформление.

**Атрибут `style`** задаёт декларации непосредственно одному элементу. Здесь нет селектора: элемент уже выбран самим атрибутом. Такое оформление трудно переиспользовать и переопределять, поэтому для обычной вёрстки предпочитаем внешний CSS-файл.

Сопоставьте три примера на слайде: отдельный ресурс, правила текущего документа, декларации одного элемента. Спросите, какой способ позволит использовать одни правила на нескольких страницах.
-->

layout: code-explain
kicker: Другие селекторы
title: Иногда достаточно атрибута или идентификатора
notes:
  - <code>*</code> выбирает все элементы; используйте его осознанно
  - <code>#registration</code> выбирает элемент с уникальным идентификатором
  - <code>input[required]</code> выбирает элементы с указанным атрибутом
---
```css
* {
  box-sizing: border-box;
}

#registration {
  scroll-margin-top: 2rem;
}

input[required] {
  border-color: #075985;
}
```
<!--
Кроме селектора элемента и класса, полезно знать три простых случая: `*` — универсальный селектор, `#registration` — селектор идентификатора, `input[required]` — атрибутный селектор. Универсальный селектор применяем осознанно, а идентификатор сохраняем уникальным.

Универсальный, ID- и атрибутный селекторы полезны, но не заменяют семантическую структуру HTML.

term: Наследование
definition: Некоторые свойства приходят к потомку от родителя, если для потомка не задано собственное значение.
points:
  - color и font-family обычно наследуются
  - margin, padding, border и width обычно не наследуются
  - Базовую типографику удобно задать один раз
---
<!--
Некоторые свойства приходят к потомку от родителя, если для потомка нет собственного значения. Обычно это `color` и `font-family`. Обычно не наследуются `margin`, `padding`, `border`, `width` и `background`.

Так удобно один раз задать базовую типографику. Но если у `main` есть рамка, у каждого абзаца внутри не появится такая же рамка.

layout: code-explain
kicker: Читаемый текст
title: База наследуется, а у карточки есть свои границы
notes:
  - Стек заканчивается общим семейством <code>sans-serif</code>, если системных шрифтов нет
  - "<code>line-height: 1.5</code> без единицы наследуется как множитель"
  - <code>65ch</code> ограничивает длину строки примерно 65 символами
  - Подчёркивание делает ссылку различимой не только по цвету
---
```css
body {
  color: #334155;
  font-family: system-ui, -apple-system, BlinkMacSystemFont, "Segoe UI", sans-serif;
  font-size: 1rem;
  line-height: 1.5;
}

.event-card { max-width: 65ch; }

.event-card a {
  color: #075985;
  text-decoration: underline;
  text-decoration-thickness: 0.1em;
}
```
<!--
Здесь базовые правила стоят на `body`, поэтому текстовые потомки наследуют цвет, семейство, размер и межстрочный интервал. Стек шрифтов идёт от предпочтительных системных имён к общему `sans-serif`: если конкретный шрифт недоступен, текст остаётся читабельным.

`font-size: 1rem` берёт привычный базовый размер документа. `line-height: 1.5` намеренно без единицы: это коэффициент, который наследуется и масштабируется вместе с размером шрифта. `max-width: 65ch` ограничивает длину строки приблизительно 65 символами; это не ширина всей раскладки, а граница меры текста.

У ссылки есть цвет и подчёркивание. Не делаем ссылку заметной только цветом. В DevTools Accessibility или в проверенном контрастном инструменте снова считываем пару `#334155` на `#fff`: 10.35:1 для основного текста.
-->

title: Псевдокласс начинается с двоеточия
---
```css
a:hover { text-decoration: underline; }
a:focus-visible { outline: 3px solid #075985; }
button:active { transform: scale(0.98); }
input:invalid { border-color: #dc2626; }
```

<!--
Псевдокласс выбирает элемент в определённом состоянии. Уже знакомые `:hover`, `:focus-visible`, `:active` и `:invalid` описывают наведение, видимый клавиатурный фокус, момент нажатия и встроенную проверку поля.

Добавим два состояния из нативной формы прошлой лекции. `input:checked` читает состояние отмеченного флажка, а `button:disabled` — недоступной кнопки. CSS не ставит галочку, не отключает кнопку и не отправляет форму: он только выбирает элемент, состояние которого уже определил браузер или HTML.

Наведение, клавиатурный фокус, нажатие, отметка и недоступность — разные состояния. Не повторяем здесь урок про фокус и наведение: дальше только увидим нативные `checked` и `disabled` рядом с ними.

---
layout: code-explain
kicker: Приложение · декоративный слой
title: "::before и ::after добавляют несущественную деталь"
notes:
  - Псевдоэлемент появляется только при заданном <code>content</code>
  - Пустая строка создаёт область для декоративной линии, а не скрытый текст
  - Существенный текст и управление остаются в HTML
---
```css
.event-card {
  position: relative;
}

.event-card::before {
  background: #7dd3fc;
  border-radius: 999px;
  content: "";
  height: 0.4rem;
  left: 1.25rem;
  position: absolute;
  top: 0;
  width: 3rem;
}
```
<!--
`::before` и `::after` создают псевдоэлементы до или после содержимого выбранного элемента. Здесь `content: ""` создаёт пустую область: это короткая цветная линия у карточки, а не текст, который нужно прочитать или перевести.

Если убрать это правило, статья, её заголовок, программа и ссылка сохраняют весь смысл. Поэтому такая деталь подходит псевдоэлементу. Не помещаем в `content` название кнопки, подсказку формы или информацию о событии: эти данные должны быть настоящим HTML, доступным без CSS.
-->

У `background-image` есть законная роль: здесь `radial-gradient` рисует декоративный узор без отдельного ресурса. Узор не сообщает ничего о событии, поэтому может исчезнуть вместе с CSS.

Изображение спикера из примера первой лекции значимо: оно часть содержания. Для него используем настоящий `img` и точный `alt`, а не фоновую картинку. В отличие от украшения, этот элемент попадает в структуру документа и может получить подпись.

Спросите: «Если убрать картинку, потеряет ли пользователь факт?» Если да — это не CSS-фон.
-->

---
layout: code-explain
kicker: Приложение · веб-шрифт
title: WOFF2 загружается отдельно, fallback остаётся сразу
notes:
  - WOFF2 — сжатый формат веб-шрифта; файл должен попасть в сборку вместе с CSS
  - <code>swap</code> сначала рисует fallback, затем подменяет его загруженным шрифтом
  - В Network фильтруем Font и проверяем запрос, статус и размер ответа
---
```css
@font-face {
  font-family: "Meetup Text";
  src: url("./meetup-text.woff2") format("woff2");
  font-display: swap;
}

body {
  font-family: "Meetup Text", system-ui, -apple-system, BlinkMacSystemFont, sans-serif;
}
```
<!--
Это контракт для проекта, который действительно поставляет `meetup-text.woff2` в тот же каталог сборки; этот учебный пример намеренно не подключает новый шрифт и использует системный стек. Не вставляем несуществующий URL в живую страницу и не зависим от CDN ради демонстрации.

`@font-face` даёт загруженному WOFF2 имя. С `font-display: swap` браузер сначала показывает системный fallback, а затем меняет его на веб-шрифт, когда ресурс готов. Поэтому fallback в `font-family` обязателен и при сетевой ошибке текст остаётся видимым.

Для диагностики откройте DevTools → Network, отфильтруйте Font, перезагрузите страницу и проверьте запрос, статус и размер файла. При 404 или блокировке CORS смотрим путь и серверные заголовки; в интерфейсе при этом остаётся fallback, а не пустой текст.
-->
