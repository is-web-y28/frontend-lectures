<!--
CSS — Cascading Style Sheets, каскадные таблицы стилей. Слово *cascading* здесь главное. К одному элементу обычно подходят несколько правил: одно задаёт цвет текста, другое — отступ, третье — состояние при фокусе. Браузер выбирает итоговое значение отдельно для каждого свойства.
-->

Перед нами не пять разных карточек, а одна карточка и выбранная декларация.
```css
.event-card {
  width: 100%;
  padding: 20px;
  color: #075985;
  border: 1px solid #cbd5e1;
}
```

<!--
Значение — не произвольное слово, а допустимая форма для конкретного свойства. Здесь `width` получает процент, `padding` — длину, `color` — цвет, а `border` — составное значение из толщины, вида линии и цвета.

Не нужно превращать это в каталог единиц. Сначала формулируем вопрос: какой аспект карточки меняем — ширину, внутреннее пространство, цвет или границу? Затем проверяем, подходит ли значение выбранному свойству. Размер текста и межстрочный интервал разберём рядом с наследованием, потому что их задача — читаемость всего документа.

<!--
У каждого CSS-объявления есть источник, или origin. Браузер даёт встроенную user-agent stylesheet, поэтому заголовок крупнее обычного текста, а ссылка заметна без авторского CSS. Пользователь может подключить собственную таблицу под свои потребности, например для более крупного текста. Автор задаёт правила в CSS-файлах, элементе `<style>` и атрибуте `style`.

Источник участвует в каскаде: обычные авторские объявления обычно переопределяют обычные правила браузера, поэтому `h1 { color: #075985; }` меняет исходный вид заголовка. Полный порядок источников и важности пока не запоминаем — далее честно сравниваем только обычные авторские объявления, а полный алгоритм будет в лекции 5.

[У одного элемента сопоставить правило из user-agent stylesheet и правило из `styles.css`; назвать источник каждого.]
-->

layout: code-explain
kicker: Авторские стили
title: Три способа подключить CSS
notes:
  - "Внешний файл: <code>&lt;link rel=&quot;stylesheet&quot;&gt;</code> — основной способ"
  - "<code>&lt;style&gt;</code>: правила только для текущего HTML-документа"
  - "Атрибут <code>style</code>: декларации только для одного элемента"
---
```html
<!-- Внешний файл -->
<link rel="stylesheet" href="styles.css">

<!-- Внутри документа -->
<style>
  h1 { color: #075985; }
</style>

<!-- У одного элемента -->
<h1 style="color: #075985;">Заголовок</h1>
```
<!--
Автор может записать CSS тремя способами. Внешняя таблица подключается в `<head>` через `link`: её можно использовать на нескольких страницах, кэшировать и редактировать отдельно от HTML. Внутренний `<style>` тоже обычно лежит в `head`, но его правила существуют только в этом документе; он годится для малого автономного примера, однако в проекте смешивает структуру и оформление.

`style` на самом `h1` задаёт декларации уже выбранному элементу — отдельный селектор не нужен. Такое правило трудно переиспользовать и переопределять, поэтому для обычной вёрстки выбираем внешний файл. Теперь, когда правило найдено, разберём, как его селектор находит элементы.

[Сопоставить на слайде отдельный ресурс, правила документа и декларацию одного элемента.]
-->

layout: code-explain
kicker: Другие селекторы
title: Иногда достаточно атрибута или идентификатора
notes:
  - <code>*</code> выбирает все элементы; используйте его осознанно
  - <code>#registration</code> выбирает элемент с уникальным идентификатором
  - <code>input[required]</code> выбирает элементы с указанным атрибутом
---
```css
* {
  box-sizing: border-box;
}

#registration {
  scroll-margin-top: 2rem;
}

input[required] {
  border-color: #075985;
}
```
<!--
Помимо имени элемента и класса, здесь встречаются три простых условия. `*` подходит каждому элементу, поэтому его используют осознанно — например, для общего `box-sizing`. `#registration` ищет единственный элемент с этим `id`, а `input[required]` — только поля `input`, у которых есть атрибут `required`.

Селектор лишь проверяет структуру, которую уже выразил HTML; он не делает идентификатор уникальным и не превращает поле в обязательное. Дальше посмотрим, как связь элементов задаёт контекст.
-->

layout: code-explain
kicker: Комбинаторы
title: Связать элементы отношением
notes:
  - Пробел — любой потомок внутри элемента
  - <code>&gt;</code> — только непосредственный ребёнок
  - <code>+</code> — следующий соседний элемент
  - <code>~</code> — любой последующий сосед
---
```css
nav a { 
  color: #172033; 
}

article > header { 
  border-bottom: 1px solid #cbd5e1; 
}

h2 + ol {
  margin-top: 0.5rem; 
}

h2 ~ p {
  color: #475569;
}
```
<!--
Комбинатор описывает отношение между частями селектора. В `nav a` пробел допускает любого потомка; `article > header` ограничивается непосредственным ребёнком; `h2 + ol` ищет ровно следующий соседний список; `h2 ~ p` — любой последующий абзац среди соседей. Поэтому `>` нельзя считать просто более заметным пробелом: он сужает множество совпадений.

Запятая работает иначе: она не связывает элементы отношением, а перечисляет независимые альтернативы. В правиле

```css
button,
input,
textarea {
  font-size: 1rem;
}
```

любой из трёх селекторов отдельно получает один намеренно общий блок деклараций. Это не «селектор кнопки с полем» и не три правила, случайно написанные рядом: автор выбрал одинаковый `font-size` для трёх типов контролов. Проверку того, что выбирает конкретный селектор, сделаем на следующем живом примере.
-->

notes:
  - "<code>border: 1px solid #cbd5e1</code> задаёт ширину, стиль и цвет границы"
  - "<code>margin: 16px 0</code> означает сверху/снизу 16px, слева/справа 0"

```css
.event-card {
  background: #ffffff;
  border: 1px solid #cbd5e1;
  border-radius: 8px;
  margin: 16px 0;
  padding: 20px;
}
```
<!--
Читаем только те сокращения, которые уже есть на карточке. В `border: 1px solid #cbd5e1` записаны толщина, вид линии и цвет. В `margin: 16px 0` первое число относится к верху и низу, второе — к левому и правому краю. Одно значение `padding: 20px` действует сразу на четыре стороны.

Поэтому текст не прилипает к рамке из-за `padding`, карточки не слипаются по вертикали из-за `margin`, а фон покрывает content и padding, но не margin.

[В DevTools открыть Computed и подсветить каждую область блочной модели.]
-->

<!--
У `content-box` значение `width` относится только к content. Поэтому при `width: 100%` боковые padding и border добавляются сверху к ширине родителя: видимый прямоугольник может выйти за его границу.

При `border-box` объявленная ширина уже включает content, padding и border. Это не делает страницу адаптивной и не расставляет элементы; оно только делает расчёт размера понятнее. Сейчас сверим разницу измерением браузера, а не формулой на веру.
-->

title: Включить padding и border в объявленный размер
---
```css
*,
*::before,
*::after {
  box-sizing: border-box;
}
```
<!--
`*` выбирает каждый элемент, а `*::before` и `*::after` добавляют к этому правилу псевдоэлементы. Поэтому базовая запись задаёт один способ расчёта и для настоящих элементов, и для будущих декоративных областей.

В основной линии достаточно узнать эти части селектора: пример с `content` для псевдоэлемента остаётся в необязательном приложении.
-->

<!--
Когда CSS кажется «неработающим», не перебираем свойства наугад. Сначала проверяем, допустимо ли значение; затем — выбрал ли селектор нужный элемент; после этого ищем победителя для конкретного свойства, отделяем собственное значение от унаследованного, проверяем состояние клавиатурного фокуса и только потом считаем padding, border, margin и `box-sizing`.

Это не обязательные шесть проверок для каждой строки CSS, а порядок, который превращает догадку в диагностику. Последняя короткая демонстрация вернёт нас к разнице одного пробела в селекторе.

---
layout: code-explain
kicker: A1 · Декоративный слой
title: "::before и ::after добавляют несущественную деталь"
notes:
  - Псевдоэлемент появляется только при заданном <code>content</code>
  - Пустая строка создаёт область для декоративной линии, а не скрытый текст
  - Существенный текст и управление остаются в HTML
---
```css
.event-card {
  position: relative;
}

.event-card::before {
  background: #7dd3fc;
  border-radius: 999px;
  content: "";
  height: 0.4rem;
  left: 1.25rem;
  position: absolute;
  top: 0;
  width: 3rem;
}
```
<!--
`::before` и `::after` создают псевдоэлементы до или после содержимого выбранного элемента. Здесь `content: ""` создаёт пустую область: это короткая цветная линия у карточки, а не текст, который нужно прочитать или перевести.

`relative`, `absolute`, `top` и `left` здесь только предварительно показывают привязку декоративной линии к карточке. Позиционирование разберём в следующей лекции; сейчас не требуется уметь воспроизвести эту раскладку. В этом необязательном примере важно понять роль `content` и проверить, что удаление декора не убирает смысл.

Если убрать это правило, статья, её заголовок, программа и ссылка сохраняют весь смысл. Поэтому такая деталь подходит псевдоэлементу. Не помещаем в `content` название кнопки, подсказку формы или информацию о событии: эти данные должны быть настоящим HTML, доступным без CSS.
-->

layout: code-explain
kicker: A3 · Веб-шрифт
title: WOFF2 загружается отдельно, fallback остаётся сразу
notes:
  - WOFF2 — сжатый формат веб-шрифта; файл должен попасть в сборку вместе с CSS
  - <code>swap</code> сначала рисует fallback, затем подменяет его загруженным шрифтом
  - В Network фильтруем Font и проверяем запрос, статус и размер ответа
---
```css
@font-face {
  font-family: "Meetup Text";
  src: url("./meetup-text.woff2") format("woff2");
  font-display: swap;
}

body {
  font-family: "Meetup Text", system-ui, -apple-system, BlinkMacSystemFont, sans-serif;
}
```
<!--
Это контракт для проекта, который действительно поставляет `meetup-text.woff2` в тот же каталог сборки. Учебная страница намеренно не подключает новый шрифт и использует системный стек: не вставляем несуществующий URL и не зависим от CDN ради примера.

`@font-face` даёт загруженному WOFF2 имя. С `font-display: swap` браузер сначала рисует системный fallback, а затем подменяет его веб-шрифтом, когда ресурс готов. Поэтому fallback в `font-family` нужен и при сетевой ошибке: текст остаётся видимым.

[В DevTools открыть Network, отфильтровать Font, перезагрузить страницу и проверить запрос, статус и размер файла.] При 404 или блокировке CORS проверяем путь и серверные заголовки; интерфейс при этом остаётся на fallback, а не превращается в пустой текст.
-->
