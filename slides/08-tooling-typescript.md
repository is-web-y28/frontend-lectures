Из корня репозитория выполните `npm ci`. Пример `examples/08-tooling-typescript` — `npm` workspace с собственным `package.json`, но общим корневым lockfile. Отдельно устанавливать зависимости в его папке не нужно. Используется Node.js 20.19+ либо 22.12+; в CI — Node 22.

При выполнении скрипта npm добавляет локальные бинарные файлы в `PATH`, поэтому глобальная установка Vite не нужна. После установки запускаем сервер разработки; `check` и `build` выполняем по задаче, не после каждого символа. `preview` требует готового `dist` и служит локальной проверкой, а не заменой размещения сайта. Остановить сервер в терминале можно через `Ctrl+C`. Теперь отделим роль зависимости в манифесте от участия её кода в результате сборки.

kicker: "Форма договора"

| Задача | Удобная запись | Зачем |
| --- | --- | --- |
| объект API | `interface Store` | расширять `extends` |

Не вводим в основном маршруте слияние деклараций и сложные пересечения. Сначала связываем каждую запись с задачей: полная заявка — объект, callback — функция, статус — набор литералов.

title: "Объект → ключ <code>count</code> → значение <code>number</code>"
notes:
  - "<code>typeof</code> и проверка <code>null</code> оставляют объект."
  - "<code>in</code> открывает свойство с типом <code>unknown</code>."

```ts
function readNumericCount(candidate: unknown) {
  if (
    typeof candidate !== 'object' ||
    candidate === null
  ) return;
  if (!('count' in candidate)) return;

  const count = candidate.count; // unknown
  if (typeof count !== 'number') return;
  return count; // number
}
```
<!--
Пройдём один и тот же `candidate` по строкам. До первого `if` о нём ничего не известно. Ранний `return` убирает не-объекты и `null`, поэтому дальше разрешён оператор `in`. Проверка ключа даёт доступ к `candidate.count`, но ещё не обещает, что внутри число. Только последний `typeof` позволяет вернуть именно числовую ветку.

[Спросить прогноз для `{ count: '2' }`, `{ count: 2 }` и `{ count: 6 }`: получим `undefined`, `2` и `6`. Затем предложить убрать только последний `if` и определить тип возвращаемого значения: `unknown`, а не `number`. Не выдавать подсказку редактора за преобразование значения.]

Это законченный маленький пример сужения, не замена `validateRegistrations`. layout: code-explain
kicker: "Проверка совместимости"
title: "<code>satisfies</code> проверяет форму, сохраняя собственный вывод выражения"
notes:
  - "Правая часть должна подойти <code>Registration</code>."
  - "Это не <code>as</code> и не слепое утверждение."
  - "Полезно для констант и фикстур."
---
```ts
const anna = {
  id: 'anna',
  name: 'Анна',
  email: 'anna@meetup.example',
  count: 1,
} satisfies Registration;
```
<!--
- **`satisfies`.** Проверяет совместимость выражения, не превращаясь в runtime-проверку; вывод зависит и от контекстного типа. Не обещаем, что любой строковый литерал всегда останется литеральным или что оператор вообще не влияет на вывод.

`satisfies` проверяет совместимость с `Registration`, но не подменяет тип выражения аннотацией `: Registration`; контекстный вывод конкретного литерала остаётся доступен там, где он важен. Поэтому это отличается от `as`, которое просит TypeScript поверить автору.
-->

layout: code-explain
kicker: "Ограниченный generic"
title: "<code>extends</code> в <code>T</code> ограничивает допустимые аргументы типа"
notes:
  - "<code>T</code> должен иметь <code>id: string</code>."
  - "Внутри функции доступен <code>item.id</code>."
  - "Это не <code>class extends</code>."
---
```ts
function idLabel<T extends { id: string }>(
  item: T,
): string {
  return `id: ${item.id}`;
}

idLabel({ id: 'anna', name: 'Анна' });
```
<!--
- **Ограничение `T` через `extends`.** Обобщённая функция может требовать наличие `id` или другого известного свойства. Это ограничение типа, не наследование JavaScript-класса.

`T extends { id: string }` не наследует код класса: оно ограничивает тип аргумента и обещает, что внутри есть `id`. Объект с дополнительным `name` тоже подходит: ограничение требует `id`, но не запрещает другие поля.
-->

layout: code-explain
kicker: "Ключи договора"
title: "<code>keyof</code> связывает имя ключа с объектом и типом его значения"
notes:
  - "<code>K</code> допускает только ключи <code>T</code>."
  - "Результат имеет тип <code>T[K]</code>."
  - "Неверный ключ заметен до запуска."
---
```ts
function readField<T, K extends keyof T>(
  item: T,
  key: K,
): T[K] {
  return item[key];
}

readField({ name: 'Анна' }, 'name');
```
<!--
- **`keyof`.** Допустимое имя ключа связывается с типом объекта; функция чтения поля не должна принимать любую строку, обещая корректный результат.

`K extends keyof T` запрещает назвать ключ, которого у объекта нет, а `T[K]` сохраняет тип именно этого поля. Функция не должна угадывать, что вернётся строка для любого `T`.
-->
