layout: code-explain
kicker: "Разбираем связь"
title: "В <code>script</code> меняем <code>.value</code>; в шаблоне читаем <code>ref</code> по имени"
notes:
  - "<code>ref(1)</code> хранит изменяемое значение."
  - "<code>count.value++</code> меняет его в JavaScript."
  - "<code>{{ count }}</code> выводит значение в шаблоне."
  - "<code>@click=\"increment\"</code> вызывает обработчик при нажатии."
---
```vue
<script setup lang="ts">
import { ref } from "vue"
const count = ref(1)
function increment() { count.value++ }
</script>
<template>
  <button type="button" @click="increment">
    +1
  </button>
  <p>Мест: {{ count }}</p>
</template>
```
<!--
`ref` создаёт контейнер, а не просто число. В `increment` обращаемся к `count.value`: это позволяет Vue заметить изменение. В шаблоне верхнеуровневый `ref` раскрывается автоматически, поэтому выводим `count` без `value`.

`@click` — сокращение `v-on:click`: оно связывает событие клика с обработчиком `increment`. Функция запускается по нажатию, а не при создании компонента. В главе о событиях расширим этот знакомый пример передачей аргумента; сейчас кнопка нужна, чтобы наблюдать причинную связь: действие меняет значение, Vue обновляет читающий его текст. Следом сравним такой контейнер с обычной переменной.
-->

layout: code-explain
kicker: "Состояние и его границы"
title: "В <code>reactive</code> меняем свойства без <code>.value</code>"
notes:
  - "<code>reactive</code> возвращает объект-прокси."
  - "Чтение и изменение свойств проходят через него."
  - "<code>draft.count</code> используется и в <code>script</code>, и в шаблоне."
---
```ts
import { reactive } from 'vue'

const draft = reactive({
  name: 'Анна', count: 2,
})
draft.count++
```
<!--
До сих пор мы хранили значение в контейнере `ref`. Для группы полей есть другой API: `reactive` принимает объект и возвращает его реактивный прокси. Прокси позволяет Vue замечать чтение и запись свойств; в показанном коде `draft.count++` обновит зависимый текст. Прямого поля `.value` у этого объекта нет.

Это не два независимых способа обновления DOM: объект внутри обычного `ref` тоже становится глубоко реактивным. Отличается внешний договор доступа. `reactive` предназначен для объектов, массивов и коллекций; отдельное число или строку храним в `ref`. Сравним, как обновить сразу несколько полей.
-->

layout: two-cols
kicker: "Состояние и его границы"
title: "В <code>ref</code> заменяем значение; в <code>reactive</code> — поля"
---
Контейнер с объектом

```ts
const selected = ref({
  name: 'Анна', count: 2,
})
selected.value = {
  name: 'Борис', count: 1,
}
```

::right::

Реактивный объект

```ts
const draft = reactive({
  name: 'Анна', count: 2,
})
draft.name = 'Борис'
draft.count = 1
```

<!--

title: "Доступ к <code>.value</code> может вызывать геттер и сеттер"
notes:
  - "<code>get value()</code> вызывается при чтении <code>cell.value</code>."
  - "<code>track</code> связывает поле с активным вычислением."

```js
let stored = 1
const cell = {
  get value() {
    track(cell, 'value')
    return stored
  },
  set value(next) {
    stored = next
    trigger(cell, 'value')
  },
}
```
<!--
Это учебный псевдокод, а не исходник Vue и не готовая реализация реактивности. В JavaScript `get value()` задаёт функцию, которая вызывается при чтении `cell.value`. `set value(next)` вызывается при присваивании `cell.value = next`. Снаружи доступ выглядит как обычная работа со свойством, но внутри можно выполнить дополнительные действия.

Условное имя `track` обозначает регистрацию связи: если сейчас выполняется отслеживаемое вычисление, оно становится потребителем пары «объект `cell` — свойство `value`». Без активного потребителя читать значение можно, но подписка на следующее присваивание обычной переменной не возникает. `trigger` обозначает уведомление связанных потребителей после изменения. Здесь намеренно опущены проверка равенства, очередь обновлений, очистка связей и внутренние оптимизации.

`ref` использует доступ через `.value`, а реактивный объект позволяет перехватывать операции над свойствами с помощью прокси. Поэтому `draft.count` может участвовать в том же механизме. Два направления явно

```ts
function onNameInput(event: Event) {
  const input = event.target
  if (!(input instanceof HTMLInputElement)) return
  name.value = input.value
}
```
```vue
<input :value="name" @input="onNameInput">
```

::right::

Связывание текстового поля

```vue
<label>Имя
  <input v-model="name" required>
</label>
<p>Черновик: {{ name }}</p>
```

В обоих случаях: `const name = ref('')`.
<!--
Слева `:value` заполняет поле из состояния, `input` сообщает об изменении, а обработчик записывает `input.value` в `ref`. Проверка `instanceof` уточняет тип `event.target`, как в лекции 08. Программное изменение `name` также попадёт в поле через `:value`.

Для стандартного текстового `input` `v-model` сокращает эту пару направлений. Ввод меняет `ref`; запись в `ref` меняет поле. Это правило связывания, а не проверки допустимости: `required` участвует в нативной форме, но пробелы и бизнес-диапазоны проверяем отдельно.

title: "Добавление проверяет и сохраняет черновик"

```ts
const nextId = ref(3)

function add() {
  if (!canSubmit.value || typeof count.value !== 'number') return
  registrations.value.push({
    id: nextId.value++, name: name.value.trim(), count: count.value,
  })
  name.value = ''
  count.value = 1
}
```
<!--
Исходные заявки имеют `id` 1 и 2, поэтому `nextId` начинается с 3. Новый идентификатор выдаётся при создании записи, а не при отображении строки. Если проверка не прошла, массив не меняется. Повторная проверка `typeof` в `add` позволяет TypeScript сузить `count`: булево значение другого `computed` само по себе не доказывает тип поля в этой функции. Иначе создаём отдельную запись с новым `id` и нормализованным именем, затем очищаем поля. Счётчик `id` подходит для этого примера в памяти; при обмене с сервером нужен другой источник уникальности.
-->

```ts
)
```

Шаблон использует `v-for="item in visible"`.
<!--
В Vue 3 на одном элементе `v-if` имеет приоритет над `v-for`. Поэтому условие не получает `item` из этой же итерации, и код слева не выражает ожидаемый отбор.

Справа фильтрация вычисляется заранее, а цикл получает готовую коллекцию. Если условие относится ко всему списку, его можно вынести на внешнюю обёртку. Выбор зависит от смысла условия, а не только от того, как убрать диагностическое сообщение.
-->

title: "Одна итерация может создавать несколько соседних узлов"
notes:
  - "<code>template</code> группирует узлы без обёртки в DOM."
  - "<code>key</code> задаётся для всей итерации."
  - "В примере группа находится внутри <code>dl</code>."

```vue
<template v-for="item in visible" :key="item.id">
  <dt>{{ item.name }}</dt>
  <dd>Мест: {{ item.count }}</dd>
</template>
```
<!--
В определениях `dl` одна заявка может занимать пару `dt` и `dd`. `template` группирует эти соседние узлы для `v-for`, не добавляя лишний DOM-элемент. Ключ относится ко всей итерации, поэтому ставится на `template`, а не только на `dt` или `dd`.

Это необязательное расширение: основному списку заявок достаточно одного `li` на итерацию. Стабильность `id` по-прежнему нужна при перестановках, но теперь идентичность относится к группе узлов.
