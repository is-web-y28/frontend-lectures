```js
const registration = {
```

<!--
После поиска Борис может стать первой видимой строкой, хотя в полной коллекции перед ним находится Анна. Поэтому кнопка должна передавать не позицию, а устойчивый `id` заявки. Строку DOM тоже можно связать с этим `id` — через обработчик или `data-*`; ненадёжна именно позиция, а не сама строка.

Для новой записи используем `crypto.randomUUID()`. В образце оставим читаемые `a`, `b`, `c`, чтобы следить за действиями. Идентификатор создаём один раз, не при каждом `render`. Но он ничего не говорит о правильности имени, почты и количества: прежде чем добавить такую запись, проверим ввод.

kicker: Граница формы
title: Сначала проверяем ввод, затем создаём заявку
notes:
  - "Проверка формы знакома по лекции 06; теперь результат нужен коллекции."
  - "<code>Number.isInteger</code> вместе с диапазоном допускает только целое число 1…5."

```js
const name = nameInput.value.trim();
const email = emailInput.value.trim();
const count = Number(countInput.value);

const validCount = Number.isInteger(count)
  && count >= 1 && count <= 5;
if (!name || !email || !validCount) return;

const record = {
  id: crypto.randomUUID(), name, email, count,
};
```
<!--
Проверку формы мы разобрали в лекции 06; здесь она остаётся входной границей коллекции. Уточнение в коде — `Number.isInteger`: вместе с диапазоном он исключает дробь, `NaN` и бесконечность.

Это сокращённая успешная ветка обработчика, не повтор реализации ошибок формы. Пока ввод не подходит, коллекция не меняется. После проверок создаём запись; краткое `name` означает `name: name`. Дальше передадим запись операции добавления, а не допишем строку прямо в DOM.
-->

---
layout: code-explain
kicker: Читаем запись
title: Spread раскрывает значения в новый контейнер
notes:
  - "<code>{ ...record }</code> создаёт объект с собственными перечислимыми свойствами записи."
  - "<code>[...records, copied]</code> переносит элементы массива и добавляет один."
  - "Вложенные объекты не копируются: их ссылки остаются общими."
---
```js
const record = { name: 'Анна', count: 1 };
const records = [record];

const copied = { ...record };
const next = [...records, copied];

copied === record; // false
next === records;  // false
next[0] === record; // true
```
<!--
Прежде чем использовать три точки при добавлении, прочитаем их отдельно. В объектном литерале `{ ...record }` они переносят собственные перечислимые свойства в новый объект: здесь имя и количество. В массиве `[...records, copied]` они подставляют элементы `records`, после которых мы дописываем `copied`. Исходный массив не меняется; результат содержит две записи.

Спросим, будет ли `next[0]` новым объектом. Нет: перенесён сам элемент, а для объекта это ссылка. Новый контейнер не обещает глубокого копирования; к этой границе вернёмся, когда будем защищать чтение. Теперь выражение добавления можно прочитать в два шага: скопировать новую запись, собрать следующий массив.
-->

---
layout: code-explain
kicker: Первый переход
title: Добавление меняет коллекцию и запускает <code>render</code>
notes:
  - "Это ранняя учебная версия: <code>registrations</code> пока обычная переменная."
  - "Новый массив — выбор операции с данными, не замена DOM."
  - "<code>render()</code> выполняется после успешного перехода."
---
```js
let registrations = [];

function addRegistration(record) {
  registrations = [...registrations, { ...record }];
  render();
}

addRegistration(record);
```
<!--
Не будем одновременно добавлять карточку в DOM и поддерживать второй список вручную. Здесь одна переменная `registrations`: сначала присваиваем ей следующий массив, затем вызываем `render`, который покажет уже новые данные.

Новый массив — наш способ реализовать операцию, а не обязательное условие отделения данных от DOM. Копия новой записи защищает её от последующего изменения исходного объекта вызывающим кодом. Переменная пока доступна всему коду рядом; ограничить доступ успеем после того, как соберём и увидим работающий цикл.
-->

layout: code-explain
kicker: Функция как значение
title: Стрелка — другая запись функции, которую можно передать
notes:
  - "Параметры стоят слева от <code>=&gt;</code>, тело — справа."
  - "Выражение без фигурных скобок возвращается автоматически."
  - "В теле с <code>{ }</code> результат задаёт <code>return</code>."
---
```js
function readCount(record) {
  return record.count;
}

const readCountArrow = (record) => record.count;
const readCountBlock = (record) => {
  return record.count;
};

readCountArrow({ count: 3 }); // 3
```
<!--
Слева от стрелки записаны параметры, справа — вычисление или тело функции. `readCountArrow` хранит функцию, а не число: число получается только при вызове со скобками. Три записи на экране для переданного объекта возвращают `count`. Если справа одно выражение, оно возвращается без `return`; фигурные скобки обозначают тело, и возврат нужно написать явно.

Стрелка не во всём равна обычной функции: собственное значение `this` она не получает. Пока мы не используем `this`; различие разберём вместе с методами объектов. Сейчас важно уметь прочитать `() => onRemove(record.id)`: это функция без параметров, которая вызовет удаление позже, а не при создании кнопки.
-->

---
layout: code-explain
kicker: Представление
title: <code>render</code> строит список из массива
notes:
  - "<code>records</code> задаёт весь видимый список; старые узлы заменяются."
  - "Знакомые DOM-операции теперь выполняются внутри отображения массива."
  - "Кнопка сообщает <code>id</code>, но не удаляет запись сама."
---
```js
function renderRegistrations(
  container, records, onRemove,
) {
  container.replaceChildren();
  for (const record of records) {
    const title = document.createElement('strong');
    title.textContent = record.name;
    const remove = document.createElement('button');
    remove.type = 'button';
    remove.textContent = `Удалить ${record.name}`;
    remove.addEventListener('click', () => {
      onRemove(record.id);
    });
    container.append(title, remove);
  }
}
```
<!--
DOM-операции знакомы по лекции 06. Новое — `records` задаёт весь результат отображения: `replaceChildren` убирает прежние узлы, затем цикл строит список заново. Повторный вызов с теми же записями не накапливает дубликаты и не меняет коллекцию.

Представление только показывает переданные записи и сообщает `id` через `onRemove(record.id)`; само оно ничего не удаляет из данных. В живом примере также есть почта, количество и пустой результат. Следом вычислим, какие записи передать при поиске.
-->

---
layout: code-explain
kicker: Отбор из массива
title: <code>filter</code> выбирает элементы, не меняя исходный массив
notes:
  - "Условие <code>count >= 2</code> выбирает двойку и тройку."
  - "Ответ функции определяет отбор, но не становится элементом результата."
  - "Новый массив содержит выбранные элементы исходного; сам исходный не меняется."
---
```js
const counts = [1, 2, 3];
const visible = counts.filter((count) => {
  return count >= 2;
});

visible; // [2, 3]
counts;  // [1, 2, 3]
```
<!--
Нужно получить числа не меньше двух, сохранив исходный набор. `filter` проверяет условие для очередного числа: для единицы оно ложно, для двойки и тройки истинно. В новый массив попадут исходные двойка и тройка, а не ответы `false`, `true`, `true`. Переданная функция задаёт условие отбора; её вызывает сам метод массива.

Спросим, какой массив получим, если всегда возвращать `false`: пустой, но `counts` останется прежним. Для объектов правило то же: выбранные записи сохраняют свои ссылки. Теперь такое условие можно записать для имени и почты заявки.
-->

---
layout: code-explain
kicker: Деструктуризация объекта
title: Деструктуризация извлекает поля в локальные имена
notes:
  - "<code>{ name, email }</code> слева от <code>=</code> — извлечение свойств, не новый объект."
  - "Имена соответствуют ключам объекта; остальные поля не нужны."
  - "Тот же шаблон можно поставить прямо в параметры функции."
---
```js
const record = {
  name: 'Анна', email: 'anna@example.com',
};
const { name, email } = record;
// То же чтение: record.name и record.email

const readName = ({ name }) => name;
readName(record); // 'Анна'
```
<!--
Фигурные скобки не всегда создают объект. В `const { name, email } = record` они описывают, какие свойства прочитать. Появятся две локальные переменные с теми же значениями, которые дали бы `record.name` и `record.email`; исходная запись не меняется. Это не глубокая копия: если извлечённое значение само объект, мы получим его ссылку.

В параметре `({ name }) => name` функция сначала получает объект, затем таким же способом извлекает имя. Поэтому в следующем поиске `({ name, email }) => { ... }` означает callback с одним объектом-параметром, а не с двумя аргументами. Можно было оставить параметр `record` и читать поля через точку: это другая запись того же чтения.
-->

---
layout: code-explain
kicker: Чистое вычисление
title: Поиск вычисляет видимые записи, не удаляя исходные
notes:
  - "Деструктуризация берёт только <code>name</code> и <code>email</code>."
  - "Пустой запрос возвращает все записи."
  - "<code>filter</code> создаёт новый массив, но не новые записи."
---
```js
function filterRegistrations(
  registrations, query,
) {
  const needle =
    String(query).trim().toLocaleLowerCase();
  if (!needle) return registrations.slice();
  return registrations.filter(({ name, email }) => {
    return name.toLocaleLowerCase().includes(needle)
      || email.toLocaleLowerCase().includes(needle);
  });
}
```
<!--
`filter` проходит по полной коллекции и возвращает другой массив совпадений, не удаляя ничего из `registrations`. Из записи берём `name` и `email`, приводим их и запрос к одному регистру. Достаточно совпадения в одном из полей: `||` связывает два условия. Поля не склеиваем, поэтому совпадение не может начаться в имени и закончиться в почте.

Пустой запрос возвращает копию массива через `slice()`, как в живом примере. Здесь опущено только приведение полей к строке: наши проверенные заявки уже содержат строки. Элементы результата остаются ссылками на те же записи — ни `slice`, ни `filter` не копируют их глубоко. Теперь подключим вычисление к событию поля и увидим разницу между видимым и общим количеством.
-->

layout: code-explain
kicker: Временное состояние интерфейса
title: Запрос меняет представление, а не коллекцию

  - "Сводка получает <code>visible</code> и <code>all</code> отдельно."

```js

  renderRegistrations(

  renderSummary(
```

<!--
В `render` видны два разных размера: `visible.length` и `registrations.length`. При запросе `boris` первый равен одному, второй — трём. Изменилось поле поиска, но не массив заявок, поэтому обработчик `input` просто вызывает новое отображение.

Запрос в этой версии живёт в `queryInput.value`. Мы не утверждаем, что весь интерфейс уже вынесен в отдельный объект состояния: пока отделили именно коллекцию заявок. Следующая кнопка, в отличие от поиска, действительно изменит её. Проверим, почему ей нужен `id`.
-->

---
layout: code-explain
kicker: Части массива
title: Найдём позицию и возьмём части до и после неё
notes:
  - "<code>findIndex</code> ждёт условие и возвращает индекс первого совпадения, иначе <code>-1</code>."
  - "<code>slice(start, end)</code> берёт от <code>start</code> включительно до <code>end</code> не включительно."
  - "Без <code>end</code> берём до конца; исходный массив не меняется."
---
```js
const ids = ['a', 'b', 'c'];
const index = ids.findIndex((id) => id === 'b');

index;                 // 1
ids.slice(0, index);    // ['a']
ids.slice(index + 1);   // ['c']
ids.findIndex((id) => id === 'x'); // -1
```
<!--
Как и `filter`, `findIndex` вызывает функцию с элементом и проверяет её результат. Но вместо массива возвращает позицию первого совпадения и останавливает поиск. Для `b` это единица, для отсутствующего `x` — минус один. Нельзя использовать `-1` как будто это найденная позиция: сначала нужно проверить отсутствие.

`slice` ничего не удаляет. Он возвращает новый массив выбранного диапазона: правая граница не входит, поэтому `slice(0, index)` заканчивается перед `b`, а `slice(index + 1)` начинается после него. Если найти первый элемент, левая часть будет пустой; если последний — пустой будет правая. Теперь соберём обе части spread и получим удаление без путаницы с индексом видимой строки.
-->

kicker: Удаление

```js
function removeRegistration(id) {
  const index = registrations.findIndex(
    (record) => record.id === id,
  );
  if (index === -1) return false;
  registrations = [
    ...registrations.slice(0, index),
    ...registrations.slice(index + 1),
  ];
  render();
  return true;
}
```

layout: code-explain
kicker: Снимок чтения
title: Снимок отделяет читателя от внутренних записей
notes:
  - "<code>map</code> собирает результаты преобразования в новый массив."
  - "<code>copyRecord</code> создаёт отдельный объект записи."
  - "Вместе они дают снимок: новый массив и новые объекты заявок."
---
```js
const counts = [1, 2];
counts.map((count) => count * 2); // [2, 4]

function copyRecord(record) {
  return { ...record };
}

function getAll() {
  return registrations.map(copyRecord);
}
```
<!--
Чтобы читатель мог изменить имя у себя, не затронув внутреннюю заявку, нужны и новый массив, и отдельные объекты записей. Разберём две части решения. `map` собирает возвращённые значения в новый массив: для `[1, 2]` преобразование `count => count * 2` даёт `[2, 4]`. В отличие от `filter`, результат функции здесь становится элементом, а не условием отбора.

В `registrations.map(copyRecord)` отдельный объект создаёт именно `copyRecord`, возвращая `{ ...record }`. Сам `map` копирования объектов не обещает: с `record => record` получился бы новый массив со старыми ссылками. Вместе `map` и `copyRecord` отделяют массив и записи снимка от внутренних данных. Пока поля — строки и число, этого достаточно; проверим границу на вложенном объекте.
-->

---
layout: default
kicker: Глубина копии
title: Новый массив не означает новые вложенные объекты
---
| Выражение | Новый контейнер | Что остаётся общей ссылкой |
|---|---|---|
| `[...records]` | массив | каждая запись |
| `{ ...record }` | запись | `record.contact`, если он объект |
| `map(record => ({ ...record }))` | массив и записи | вложенные объекты записей |

<!--
Сравните уровни: `[...records]` копирует контейнер, но сохраняет ссылки на записи. `{ ...record }` копирует запись, но сохраняет ссылки на её вложенные объекты. В `record => ({ ...record })` круглые скобки нужны, чтобы вернуть объект как выражение: без них фигурные скобки означали бы тело функции. `map` с таким callback делает оба первых шага, не рекурсивное копирование всего графа.

В текущих заявках все поля — примитивы, поэтому снимок из предыдущего слайда подходит. Для вложенного объекта граница другая: если `record.contact` — объект, у `{ ...record }` будет своё поле `name`, но прежняя ссылка на `contact`. Присваивание `copy.name = 'Аннушка'` не меняет исходное имя; `copy.contact.email = 'shared@example.com'` меняет общую вложенную почту. Даже `map` с копией каждой записи сохраняет тот же `contact`. Копии защищают чтение; теперь скроем саму переменную коллекции и оставим снаружи только операции.
-->

layout: code-explain
kicker: Область видимости и замыкание
title: Внутренняя функция сохраняет доступ к внешней переменной
notes:
  - "Вложенная функция ищет <code>count</code> в области, где была создана."
  - "Возвращается объект с функциями, а не значение счётчика."
  - "Доступ сохраняется и после завершения <code>createCounter()</code>: это замыкание."
---
```js
function createCounter() {
  let count = 0;
  return {
    increment: () => ++count,
    getCount: () => count,
  };
}

const a = createCounter();
a.increment();
a.getCount(); // 1
```
<!--
Сначала разберём механизм без коллекции и копий. `count` объявлен внутри `createCounter`, поэтому внешний код не может прочитать эту переменную по имени. Вложенные стрелки созданы там же: при обращении к `count` они ищут имя в окружающей области. Набор доступных им переменных и связей областей называют лексическим окружением; место поиска определяется расположением кода, а не тем, кто вызвал функцию.

`return` отдаёт объект с двумя функциями. Сам вызов `createCounter` уже завершён, но `a.increment()` продолжает менять ту же переменную, а `a.getCount()` читает её новое значение. Функцию вместе с сохранённым доступом к внешним переменным называют замыканием. Это не застывшая копия нуля: сохраняется доступ к переменной. Функцию, которая создаёт и возвращает такие объекты, называют фабрикой. Проверим, разделяют ли два вызова фабрики один счётчик.
-->

---
layout: code-explain
kicker: Применяем замыкание
title: Фабрика закрывает коллекцию и выдаёт операции
notes:
  - "<code>initial = []</code> задаёт пустой массив, если аргумент не передан."
  - "<code>copyRecord</code> — уже разобранная функция копии записи."
  - "API <code>getAll</code>/<code>add</code> ограничивает доступ, но сам не проверяет поля."
---
```js
function createRegistrationStore(initial = []) {
  let registrations = initial.map(copyRecord);

  function getAll() {
    return registrations.map(copyRecord);
  }
  function add(record) {
    registrations = [
      ...registrations, copyRecord(record),
    ];
  }
  return { getAll, add };
}
```
<!--
Это тот же приём, что у счётчика: внешний вызов создаёт локальную переменную, а возвращённые функции сохраняют доступ к ней. Начальный массив копируем через знакомый `map(copyRecord)`, чтобы вызывающий код не удержал внутренние записи. Запись `initial = []` — значение параметра по умолчанию: если аргумент не передали или передали `undefined`, начнём с пустого массива.

`return { getAll, add }` — краткая запись объекта с полями `getAll: getAll` и `add: add`. Внешнему коду выданы функции, не сама `registrations`. Этот набор доступных операций и правил их использования назовём API хранилища. Методы обращаются к переменной окружения, а не к `this`. Теперь `add` не вызывает `render`: обработчик изменит данные через хранилище и отдельно обновит страницу. Добавим удаление в тот же набор операций.

Не смешиваем доступ и проверку данных: показанный `add` копирует и добавляет запись, но не проверяет её поля или уникальность `id`. До вызова из формы ввод проверяет обработчик; позднее при загрузке сохранения данные проверит отдельный валидатор. Замыкание не создаёт этих проверок автоматически.
-->

kicker: Общее окружение
title: <code>getAll</code> и <code>remove</code> обращаются к одной переменной
notes:
  - "Фрагмент находится внутри уже показанной фабрики."
  - "<code>-1</code> означает отсутствие записи."
  - "Две части <code>slice</code> дают новый массив без найденного <code>id</code>."
---
```js
function remove(id) {
  const index = registrations.findIndex(
    (record) => record.id === id,
  );
  if (index === -1) return false;
  registrations = [
    ...registrations.slice(0, index),
    ...registrations.slice(index + 1),
  ];
  return true;
}

return { getAll, add, remove };
```
<!--
`remove` не передаёт массив в `getAll`, но после удаления чтение всё равно увидит новый список. Обе функции созданы внутри одного вызова фабрики и обращаются к одной переменной `registrations`. Присваивание меняет её значение, не создаёт отдельную коллекцию только для `remove`.

Как у `increment` и `getCount`, здесь функции разделяют одну переменную своего вызова фабрики. Второй вызов `createRegistrationStore` создаст другую переменную и другой набор функций. Данные уже скрыты, а для чтения выдаются копии. На таком снимке отдельно сравним две роли знакомых трёх точек: передачу отдельных аргументов и их сбор в массив.
-->

layout: code-explain
kicker: Rest и spread
title: Rest собирает записи, spread передаёт их в функцию
notes:
  - "В объявлении <code>...records</code> — rest и создаёт массив аргументов."
  - "В вызове <code>...store.getAll()</code> — spread и раскрывает массив."

```js
function totalParticipants(...records) {
  let total = 0;
  for (const { count } of records) total += count;
  return total;
}

const people = totalParticipants(...store.getAll());
```
<!--
Здесь не новая обязанность хранилища, а сравнение двух форм передачи данных. Для `totalParticipants` выбрана сигнатура с отдельными заявками: rest собирает их в массив `records`, а spread в вызове раскрывает полученный снимок в аргументы. Можно было написать функцию с обычным параметром-массивом и передать `store.getAll()` без spread.

В обоих вариантах цикл складывал бы `count`; `people` — сумма участников, не длина списка заявок. Отдельного счётчика людей в интерфейсе этого примера нет. Ни rest, ни spread не копируют объекты глубоко. Мы собрали небольшой API, который скрывает коллекцию и выдаёт операции. Такой же набор методов можно реализовать классом — сравним, где тогда будут данные и кто сможет их менять.

<!--
Фабрика уже решает задачу. Класс здесь не «следующий обязательный уровень», а второй способ выразить тот же API `getAll`, `add`, `remove`.

layout: code-explain
kicker: Объекты без классов
title: Прототип — следующий объект при поиске свойства
notes:
  - "<code>shared</code> — прототип <code>anna</code>: объект, где продолжается поиск."
  - "<code>name</code> записано в самом <code>anna</code>."
  - "Для <code>group</code> JavaScript переходит по связи к <code>shared</code>."
---
```js
const shared = {
  group: 'Frontend Meetup',
};

const anna = Object.create(shared);
anna.name = 'Анна';

anna.name;  // 'Анна'
anna.group; // 'Frontend Meetup'
```
<!--
`Object.create(shared)` создаёт новый объект с внутренней связью на `shared`. Объект, к которому поиск переходит при отсутствии собственного свойства, называется прототипом. Создание связи не копирует поля из `shared` в `anna`: у Анны появилось только собственное `name`.

Попросите предсказать два чтения. Для `anna.name` значение находится сразу в объекте Анны. Для `anna.group` собственного свойства нет, поэтому JavaScript обращается к связанному `shared`. Это поиск свойства, а не объединение двух объектов.
-->

---
layout: code-explain
kicker: Поиск свойства
title: Сначала своё свойство, затем — свойство связанного объекта
notes:
  - "Собственное <code>anna.group</code> перекрывает одноимённое свойство <code>shared</code>."
  - "<code>shared.group</code> не меняется: данные не были скопированы и не являются одним полем."
  - "Перекрытие действует только при обращении через <code>anna</code>."
---
```js
const shared = {
  group: 'Frontend Meetup',
};
const anna = Object.create(shared);

anna.group = 'Спикеры';

anna.group;   // 'Спикеры'
shared.group; // 'Frontend Meetup'
```
<!--
Теперь в `anna` создаётся собственное свойство с тем же именем. При чтении поиск останавливается на первом найденном свойстве, поэтому через `anna` видим «Спикеры».

У `shared` осталось исходное значение. Это называют перекрытием: свойство ниже по связи скрывает одноимённое свойство выше. Связь объектов не означает, что значения переносятся или синхронизируются между объектами.
-->

---
layout: code-explain
kicker: Наблюдаем связь
title: У поиска есть проверяемые шаги и конец
notes:
  - "<code>Object.hasOwn</code> проверяет только сам объект, не продолжая поиск."
  - "<code>Object.getPrototypeOf</code> показывает следующий объект в цепочке."
  - "После <code>Object.prototype</code> стоит <code>null</code>: дальше искать негде."

```js
const shared = { group: 'Frontend Meetup' };
const anna = Object.create(shared);

Object.hasOwn(anna, 'group'); // false
Object.getPrototypeOf(anna) === shared; // true

const root = Object.prototype;
Object.getPrototypeOf(shared) === root; // true
Object.getPrototypeOf(root); // null
```
<!--
Здесь снова версия до перекрытия: `group` не собственное свойство Анны. `Object.hasOwn` отвечает именно на этот узкий вопрос; он не говорит, доступно ли свойство вообще.

`Object.getPrototypeOf` показывает следующий объект, куда перейдёт поиск. У нашего `shared` следующий объект — стандартный `Object.prototype`; после него — `null`. `null` — понятный конец цепочки: если имя не нашли до него, результат чтения будет `undefined`.
-->

kicker: Создание экземпляра

```js
class RegistrationStore {
  constructor(initial = []) {
    this.registrations = initial.map(copyRecord);
  }

  getAll() {
    return this.registrations.map(copyRecord);
  }
}

const store = new RegistrationStore([]);
```
<!--
`class` объявляет класс — описание создания экземпляров с данными и методами. `constructor` — специальный метод инициализации. Выражение `new RegistrationStore([])` создаёт объект-экземпляр, связывает его с объектом методов класса и запускает конструктор с новым объектом как `this`. Здесь конструктор ничего явно не возвращает: результатом `new` становится созданный экземпляр.

Внутри конструктора `this` — именно создаваемый `store`, поэтому `this.registrations` становится его собственным массивом. `map(copyRecord)` уже знакомо: хранилище получает копии начальных записей, а не сам входной массив. Запись `getAll() {}` размещает одну функцию на `RegistrationStore.prototype`; она не создаётся заново для каждого объекта.

title: Стрелка берёт <code>this</code> из создания экземпляра

layout: code-explain
kicker: Поток исключения
title: <code>throw</code> прерывает путь до ближайшего <code>catch</code>
notes:
  - "При неверном тексте функция не возвращает значение: она бросает ошибку."
  - "Строка после вызова <code>readCount</code> пропускается."
  - "<code>catch</code> получает ошибку, дошедшую до вызывающего кода."
---
```js
function readCount(text) {
  const count = Number(text);
  if (!Number.isInteger(count)) {
    throw new TypeError('Нужно целое число.');
  }
  return count;
}

try {
  const count = readCount('два');
  console.log(count); // не выполнится
} catch (error) {
  console.log(error.name);
}
console.log('Продолжаем');
```
<!--
Это самостоятельный пример потока управления. `readCount('два')` встречает `throw`; обычный путь функции прекращается, `return count` не достигается, как и следующий `console.log` в `try`.

`new TypeError(...)` создаёт объект ошибки с именем `TypeError` и сообщением; сам по себе `new` его не бросает — это делает `throw`. Блок `try` окружает операцию, а `catch (error)` получает выброшенный объект, даже если ошибка пришла из вызванной функции. Здесь он напечатает `TypeError`, затем выполнение продолжится после `catch` и напечатает «Продолжаем». Без подходящего обработчика ошибка распространяется дальше, а текущая операция обрывается. Сравним это с обычным возвращаемым результатом.
-->

title: Правильный JSON ещё не означает правильные заявки
notes:
  - "Это часть <code>validateRegistrations</code> из <code>storage.js</code>."
  - "<code>throw</code> передаёт неподходящие данные вызывающему <code>load</code>."

```js
if (!Array.isArray(value)) {
  throw new TypeError('Ожидался массив заявок.');
}

for (const record of value) {
  if (!record || typeof record !== 'object'
      || Array.isArray(record)) {
    throw new TypeError('Нужен объект заявки.');
  }
  if (!Number.isInteger(record.count)
      || record.count < 1 || record.count > 5) {
    throw new TypeError('Число участников: 1–5.');
  }
}
```
<!--
`JSON.parse` проверяет синтаксис текста, но не договор наших заявок. Валидатор сначала требует массив, затем объект-заявку, а в полном варианте — уникальный непустой `id`, имя без краевых пробелов, непустую почту и `count` от 1 до 5.

Только после этой границы данные доходят до фабрики. Теперь определим одну функцию записи, которая проверяет данные до сериализации; далее она будет использоваться в обработчиках.
-->

kicker: Одна операция записи
title: <code>saveRegistrations</code> проверяет, превращает и записывает

```js
function saveRegistrations(records) {

    validateRegistrations(records);

```

title: <code>reduce</code> сворачивает коллекцию в одно значение
notes:
  - "Начальное <code>0</code> делает пустую коллекцию корректным случаем."
  - "<code>count</code> уже прошёл проверку."
  - "Это чтение снимка, а не изменение <code>store</code>."
---
```js
const total = store.getAll().reduce(
  (sum, { count }) => sum + count,
  0,
);
```
<!--
`reduce` передаёт накопленную сумму и очередную запись функции. Начальное `0` важно: пустая коллекция тогда даёт ноль, а не пытается взять отсутствующий первый элемент.

Это сумма участников, не число заявок. Вычисление читает снимок и не меняет хранилище.
-->

---
layout: code-explain
kicker: Приложение · приватное поле
title: <code>#events</code> доступно только телу своего класса
notes:
  - "Приватность задаёт сам язык, не соглашение об имени."
  - "Метод возвращает снимок журнала, а не сам массив."
  - "Это самостоятельный класс, без наследования."
---
```js
class AuditLog {
  #events = [];

  add(type, id) {
    this.#events.push({ type, id });
  }

  getAll() {
    return this.#events.map(
      (event) => ({ ...event }),
    );
  }
}
```
<!--
Объявление `#events` задаёт приватное поле. Обращение `log.#events` вне тела `AuditLog` — синтаксическая ошибка, а `log.events` — другое, обычное свойство, которое ничего не открывает. Это языковая граница, не подчёркивание в имени.

`getAll` копирует и массив, и плоские объекты событий, иначе через выданную запись можно было бы изменить журнал. Приватность поля не делает автоматически приватными все ссылки, которые метод отдаёт наружу. При необходимости журнал можно передать хранилищу отдельным объектом — это композиция, не наследование.
-->

---
layout: code-explain
kicker: Приложение · специализация
title: <code>extends</code>, переопределение и <code>super</code> сохраняют базовое действие
notes:
  - "<code>AuditedStore</code> остаётся разновидностью <code>RegistrationStore</code>."
  - "Переопределённый <code>add</code> сначала вызывает базовую операцию."
  - "Здесь нет приватного поля: это отдельный механизм."
---
```js
import { RegistrationStore } from './state.js';

class AuditedStore extends RegistrationStore {
  add(record) {
    super.add(record);
    console.log('Добавлена:', record.id);
  }
}

const store = new AuditedStore();
store.add({
  id: 'a', name: 'Анна',
  email: 'anna@example.com', count: 1,
});
```
<!--
Здесь импортирована полная реализация `RegistrationStore` из `state.js`, где есть `add`, а не сокращённый класс только с `getAll` из вводного примера. `extends` выражает отношение «является разновидностью». Если подкласс не пишет свой конструктор, создание экземпляра передаёт аргументы конструктору базового класса. Переопределённый `add` вызывает `super.add(record)`, чтобы базовое добавление действительно выполнилось, и затем выводит сообщение об аудите.

Наследование не является универсальным способом убрать повтор кода. Для хранения, DOM и координации в основной программе яснее уже использованная композиция модулей.
-->

layout: code-explain
kicker: Приложение · тонкость конструктора
title: Явно возвращённый объект может заменить результат <code>new</code>
notes:
  - "Это дополнительная тонкость, не правило для обычного конструктора."
  - "Возвращённый объект заменяет созданный экземпляр."
  - "Без такого возврата <code>new</code> даёт обычный экземпляр класса."
---
```js
class Replacement {
  constructor() {
    return { kind: 'замена экземпляра' };
  }
}

const result = new Replacement();
result.kind; // 'замена экземпляра'
```
<!--
Обычное создание экземпляра уже относится к основному материалу. Здесь только продвинутое исключение: если конструктор явно вернёт объект, именно он станет результатом `new`.

Для обычного конструктора такого возврата не пишут: результатом остаётся созданный экземпляр, связанный со своим прототипом. Эта тонкость не нужна, чтобы понять или запустить форму заявок.
-->

kicker: Приложение · ограничения JSON
title: JSON не сохраняет все значения JavaScript
---
| Значение | При <code>JSON.stringify</code> | Следствие |
|---|---|---|
| <code>Date</code> | строка через <code>toJSON</code> | <code>parse</code> не вернёт <code>Date</code> |
| <code>undefined</code> / функция | в объекте пропускаются | данные теряются |
| <code>NaN</code> / <code>Infinity</code> | становятся <code>null</code> | число меняется |
| <code>BigInt</code> / цикл | <code>TypeError</code> | нужен иной договор |
<!--
JSON — ограниченный формат, не универсальная глубокая копия. Дата становится строкой, функции и `undefined` в объектах пропускаются, а `NaN` и бесконечность меняются на `null`.

Наши строки и небольшое целое число подходят этому договору. Для сложных значений сначала определяют формат и восстановление, а не предполагают, что JSON сохранит всё.
-->

layout: code-explain
kicker: Приложение · несколько вкладок
title: <code>storage</code> сообщает об изменениях в других окнах
notes:
  - "Событие несёт ключ, прежнюю и новую строки, область хранения."
  - "Окно, выполнившее запись, собственного события не получает."
  - "Для применения понадобятся проверка, <code>render</code> и политика конфликтов."
---
```js
window.addEventListener('storage', (event) => {
  if (event.key !== STORAGE_KEY) return;
  console.log(
    event.key,
    event.oldValue,
    event.newValue,
    event.storageArea,
  );
});
```
<!--
Для `localStorage` другая вкладка того же origin получает событие после изменения. Окно-источник не получает собственного события; доступны ключ, прежняя и новая строки, а также область хранения.

Это наблюдение, не готовая синхронизация. Чтобы применить изменение, нужны повторная проверка, обновление DOM и правило конфликта с локальным вводом.
-->
